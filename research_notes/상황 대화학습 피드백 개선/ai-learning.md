# AI 학습설계와 평가 전문가 검토

검토일: 2026-10-22. 범위: W07 1~26쪽, lesson-turn 프롬프트와 서버 처리, review-quiz, evals. 구현 전 읽은 코드 기준이다. 아래 구현안은 연구에서 직접 검증된 처방이 아니라 서비스에 맞춘 설계 가설이다.

## 1. 어느 정도의 도움을 언제 제공할 것인가?

### Takeaway
이미 가르친 표현에는 짧은 오류 단서를 먼저 제공하고 같은 목표에서 다시 막히면 패턴을 제공한다. 처음 배우는 표현은 기존 패턴 모달을 유지한다. 상황 대화에서는 같은 문장을 다시 쓰게 하기보다 다른 내용의 자연스러운 질문으로 적용 기회를 만든다.

### Cited Findings
- W07 22~23쪽은 암시적인 도움에서 시작해 필요할 때 명시적으로 바꾸는 도움 조절을 설명한다. 24쪽은 수준, 정확성/유창성 목표, 시점과 매체를 함께 고려하라고 한다. 25~26쪽은 오류 위치와 규칙 단서, 정답 제시를 구분한다. [제공 자료 추출](./source-pages.txt)
- Bastani 외의 고등학교 수학 현장 실험에서는 AI를 쓸 때의 연습 성과와 AI를 제거한 시험 성과가 달랐다. 일반형 AI 집단의 시험 점수 하락은 보호 지침을 넣은 튜터 집단에서 대부분 완화됐지만, 튜터 집단의 무AI 시험이 대조 집단보다 좋아졌다는 증거는 없었다. 따라서 힌트 중심 AI가 학습효과를 보장한다고 해석할 수 없다. [저자 공개 원문, 초록 및 4쪽](https://hamsabastani.github.io/education_llm.pdf)
- 현재 시스템은 needs_correction에서 expression 모달을 반드시 요구한다. 한국어 단서만 주는 경로가 없고, 원어민이 다르게 표현할 문장을 교정 대상으로 정의한다. [lesson-turn prompt](../../supabase/functions/_shared/prompts/lesson-turn.ts), [서버 검사](../../supabase/functions/lesson-turn/core.ts)

### Inferences
- **영어 전문가와 상호 검토한 합의:** 오류 하나를 고른다. 의미 전달을 막는 오류, 현재 상황의 목표 표현, 되풀이되는 오류 순으로 우선한다. 자연스러운 대안이나 짧은 응답을 선호 표현과 다르다는 이유로 교정하지 않는다.
- **영어 전문가에게 제기한 반론:** knownItems에는 seen도 들어가므로 known 문자열만으로 자기수정 가능성을 가정할 수 없다. taught/used/recalled인 항목만 cue 후보로 삼는다. 이 상태도 숙달이나 오류 원인을 증명하지 않으므로 '알고도 실수했다'는 설명은 금지한다. 영어 전문가가 동의했다.
- **영어 전문가가 제기한 보완:** 같은 목표의 재실패 여부는 명시적 target 메타로 판정한다. 문장 유사도는 오류 종류의 동일성을 보장하지 않는다. 이에 동의했다.
- 최소 단계는 cue와 pattern 두 개면 충분하다. 모든 학습자에게 네 단계의 고정 절차를 강요할 필요는 없다. cue는 오류 구간 하나와 짧은 한국어 규칙 단서로 제한한다. 정답 낱말, 완성 문장, 새 어휘 목록을 동시에 주지 않는다.
- cue 후 자연스러운 다른 표현으로 답했다면 대화를 진행한다. 목표 패턴을 회피했다고 무조건 오답 처리하면 상황 대화가 빈칸 퀴즈가 된다. 다만 목표 항목의 사용 성공으로는 기록하지 않는다.
- 기존의 다른 질문에 적용하기 규칙을 유지하면 원문 자기수정 실험의 repair와 같지 않다. 제품 안에서는 '단서 뒤 적용'으로 부른다.
- unknown target을 cue만으로 가르치려 하지 않는다. 처음 보는 표현에는 패턴을 제공하고 다음 질문에서 스스로 내용을 채우게 한다.
- 재실패 시 힌트를 반복해 늘리기보다 마지막 cue와 현재 target이 같은지를 보고 한 번 pattern으로 강화한다. 최근 대화에 필요한 상태만 저장하면 새 테이블 없이 구현할 수 있다.

### Gaps
- two-stage cue→pattern이 한국어권 성인의 영어 상황 대화에서 기존 모달보다 학습을 개선하는지는 아직 검증하지 않았다.
- taught/used/recalled는 교수 이력의 대리변수다. 잠재 능력, 피로, 타이핑 실수, 학습자 부담을 직접 측정하지 않는다.
- 다른 질문을 제시하면 오류 종류와 문장 난도가 함께 변할 수 있다. 즉시 성공/실패만으로 cue의 인과효과를 판단할 수 없다.

## 2. 무엇을 학습 성공으로 기록하고 무엇을 분리해야 하는가?

### Takeaway
표현 문자열이 답변에 들어갔다는 사실만으로 사용 성공을 기록하지 않는다. 대화 중 도움을 받은 적용, 당일 확인, 다음 학습일의 무도움 회상, 새로운 상황에서의 전이를 나누어 해석한다.

### Cited Findings
- 외국어 단어쌍을 학습한 대학생 실험에서 한 번 회상에 성공한 뒤에도 회상을 반복한 조건은 지연 검사에서 이점을 보였다. 학습자가 예상한 성과는 실제 성과와 일치하지 않았다. 이 연구는 단어 기억 연구이며 자연스러운 대화 능력 전반의 증거는 아니다. [Karpicke & Roediger 2008, 저자 공개 원문](https://learninglab.psych.purdue.edu/downloads/2008/2008_Karpicke_Roediger_Science.pdf)
- 기존 recordItems는 verdict 없이 itemAppearsIn 문자열 검사로 used 이벤트와 상태 승격을 만든다. 따라서 한국어 혼용, 역할 이탈, 해당 표현을 잘못 사용한 답도 문자열을 포함하면 used가 될 수 있다. 최근 모달만 aided 판정에 포함하므로 단서 경로를 추가할 때 이 부분을 함께 바꿔야 한다. [lesson-turn handler](../../supabase/functions/lesson-turn/handler.ts), [문자열 검사](../../supabase/functions/_shared/text.ts)
- 기존 복습은 A 단계 첫 시도로만 SRS 간격을 변경하고 C 당일 확인을 장기 기억으로 계산하지 않는다. 이 구분은 유지할 가치가 있다. [review-quiz handler](../../supabase/functions/review-quiz/handler.ts)

### Inferences
- 최소 수정에서는 natural 응답에서만 used를 기록한다. 정확한 항목이 들어간 문장에 다른 오류가 있어도 기록을 놓칠 수 있지만, 오답 사용을 성취로 집계하는 것보다 보수적이다. target별 정확도를 별도로 채점하는 기능은 이번 최소안에 필요하지 않다.
- cue와 pattern의 target을 도움 이력에 남겨 다음 성공을 aided로 표시한다. 모달이 없다고 무도움으로 계산하지 않는다. 말풍선에 제시된 정답을 베낀 경우도 무도움 회상이 아니다.
- used는 장면에서 사용한 관측값이다. mastered 또는 습득 완료로 이름을 바꾸지 않는다. substring matching은 문맥상 적절성이나 자발적 산출을 확정하지 못한다.
- 단계별 지표 정의:
  - `aided application`: 최근 같은 목표에 cue 또는 pattern을 받은 후 자연스러운 답에서 항목을 사용한 횟수/기회 수.
  - `delayed unaided recall`: 후속 학습일 A의 첫 시도에서 도움 없이 맞힌 항목 수/응시 항목 수.
  - `transfer`: 학습 때와 다른 내용 또는 장면에서, 목표 표현을 보여주지 않고, 의미가 맞는 응답을 산출한 수/기회 수. 같은 표현을 쓰지 않은 자연스러운 답도 의사소통 성공으로 별도 기록한다.
  - 사용 시간, 완료율, 메시지 수, 교정 수는 참여 지표다. 학습효과의 대체값으로 보고하지 않는다.
- 기존 A의 target 상황 문제는 한국어 의미를 표시하며 특정 표현 사용을 요구한다. 이는 단서가 있는 목표 표현 검사다. 일반적인 무단서 전이 검사라고 부르려면 별도 조건이 필요하다. 현재 회상 검사를 억지로 전이 검사로 재명명하지 않는다.
- 사용자 실험 가설: 기존 모달 대조군과 cue 우선 실험군을 학습자 단위로 나누고, 수준과 연습량을 함께 기록한다. 주 결과는 며칠 후 첫 무도움 검사와 새로운 상황에서의 의미 전달 성공이다. 즉시 성공률, 교정 중 이탈률, 반복 교정 수를 보조 지표로 쓴다. 표본 수는 효과 크기 가정과 검정력 계산 후 결정한다.

### Gaps
- 현재 저장값만으로 장기 습득의 인과효과나 진짜 자발적 사용을 증명할 수 없다.
- 자연스러움 판정도 모델 오류가 가능하다. natural을 통과 조건으로 추가해도 used가 완벽한 교육 측정값이 되는 것은 아니다.
- 이번 수정에 새로운 실험 배정, 통계 추정, 새 성과 대시보드까지 넣는 것은 범위를 넘는다. 지표 정의와 현재 기록의 오염 방지가 우선이다.

## 3. LLM 출력 평가와 실제 학습효과를 어떻게 검증할 것인가?

### Takeaway
프롬프트의 친절함이나 정답률만 평가하지 말고 오류 진단, 도움의 적절성, 답안 유출, 상황 유지, 단계 전환을 따로 평가한다. 자동 평가가 통과했다는 결과는 모델 행동의 검증이며 인간 학습효과의 검증이 아니다.

### Cited Findings
- MRBench는 192개 수학 교육 대화와 1,596개 응답을 대상으로 오류 식별, 오류 위치, 답안 노출, 지도, 실행 가능성, 일관성, 말투, 인간다움의 여덟 축과 인간 주석을 제공한다. 이처럼 교육 행동은 단일 유용성 점수보다 여러 구체적 기준으로 평가할 수 있다. 영어 대화 서비스에 곧바로 같은 타당도가 생기는 것은 아니다. [Maurya 외 2025, 원문](https://aclanthology.org/2025.naacl-long.57.pdf)
- 선택적 LLM 평가 연구는 모델 평가를 무비판적으로 신뢰하지 않고 인간과의 일치 가능성을 교정해 선택적으로 신뢰하는 접근을 제안한다. 우리 서비스의 judge는 이 연구의 보장 조건을 구현하지 않았으므로 연구의 일치율 보장을 가져올 수 없다. [Jung 외, Trust or Escalate](https://arxiv.org/abs/2407.18370)
- 기존 evalLesson은 모든 case의 knownItems를 빈 배열로 설정한 단일 턴 평가다. 완성 답안 유출은 모달이 있을 때만 평가하고 partner 대사는 포함하지 않는다. 맞는 긴 답의 natural 비율은 정보로만 출력하며 실패 gate는 아니다. [evals/run.ts](../../evals/run.ts)
- 현재 서버 유출 검사는 hidden_correction을 기준으로 모달/코치 안내를 확인한다. 문자/단어 중복 휴리스틱이며 의미상 동등한 답 노출을 완전히 탐지하지 못한다. [서버 검사](../../supabase/functions/lesson-turn/core.ts), [leaksFullAnswer](../../supabase/functions/_shared/text.ts)

### Inferences
- 최소 acceptance tests:

| 조건 | 기대 결과 | 검사 방식 |
| --- | --- | --- |
| taught 표현 첫 오류, 최근 cue 없음 | cue, 모달 없음, 목표 메타 1개, 한국어 단서 | 단위 검사 + 고정 LLM 사례 |
| 동일 target cue 후 재실패 | pattern 모달, 동일 목표, 도움 강화 | 이전 턴 메타를 넣은 연속 사례 |
| seen-only 또는 새 표현 | pattern 모달, 막연한 cue만 주지 않음 | 서버/모델 사례 |
| cue 후 다른 자연스러운 표현으로 응답 | natural, 불필요한 강제 재시도 없음 | 의미 판단 사례 |
| cue 후 목표를 적절히 사용 | used + aided true | 저장 계층 테스트 |
| 한국어/이탈/오답 속 target 문자열 | used 이벤트/승격 없음 | 저장 계층 테스트 |
| partner가 완성 교정문을 먼저 말함 | 유출 검사 실패 또는 재생성 | 결정적 검사 |
| 모달 없이 coach_note에 완성답 | 유출 검사 실패 | 결정적 검사 |
| 짧고 적절한 답, 동등한 자연스러운 대안 | natural, 모달/단서 없음 | 과잉교정 사례 |
| 여러 오류가 있는 답 | 단서 목표 하나, 새 항목 예산 준수 | 스키마/의미 판단 |
| 교정 뒤 새 질문 | 장면과 목표가 유지되며 내용은 바뀜 | 기존 반복 judge + 장면 rubric |
| 같은 요청 id 재전송 | 도움 단계나 used 이벤트 중복 없음 | 기존 멱등성 회귀 테스트 |

- 자연스러운 답을 오답으로 잡는 비율은 실패 gate에 포함한다. '오류를 많이 잡는다'만 최적화하면 과잉교정이 좋아 보인다.
- 단위 테스트는 알려진 저장 오류와 단계 규칙을 확정한다. live eval은 모델이 실제로 규칙을 따르는지 본다. 실제 사용자의 학습 실험은 지연 성과를 본다. 세 결과를 서로 대체하지 않는다.
- judge rubric은 '좋은가?' 대신 '이번 질문에 적절한 짧은 답을 부당하게 교정했는가?', '정답 없이 다음 적용이 가능한 단서인가?', '다음 질문이 같은 언어 기능을 자연스럽게 요구하는가?'처럼 분리한다.
- 경계 사례와 judge 불일치 사례는 영어교육 검토자가 표본 검수한다. 동일 모델의 생성과 자기평가가 일치한다고 정답으로 확정하지 않는다.
- 출력 비교는 같은 입력/동일 모델 설정으로 기존과 변경 프롬프트를 비교한다. 처음 보고 손본 사례는 개발 세트로 남기고, 새 회귀 사례를 평가에 넣어 과적합을 줄인다. 합성 학습자의 답은 통제용 자극이며 실제 학습자 향상을 뜻하지 않는다.

### Gaps
- 문자 중복 기반 유출 검사는 짧은 관용구와 자연스러운 partner 대사를 잘못 잡을 수 있다. 짧은 답 사례와 의미적 유출 사례를 함께 살펴야 한다.
- 유한한 고정 사례 통과는 모든 장면과 모든 모델 버전의 성능 보장이 아니다. 이번 실행의 모델/프롬프트 버전과 실행 여부를 결과에 함께 남겨야 한다.
- 인간 검수 표본이나 실제 학습자 실험을 하지 않았다면 '학습효과가 검증됐다'고 보고하지 않는다.
