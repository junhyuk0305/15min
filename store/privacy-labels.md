# 개인정보 라벨과 데이터 보안 양식

App Store 개인정보 라벨과 Google Play 데이터 보안 양식에 넣을 답입니다.
`docs/legal/개인정보처리방침.md` 2절과 같은 항목만 적습니다. 방침이나 수집 항목이 바뀌면 이 파일과 두 스토어 답을 같이 고칩니다.

## 0. 두 양식이 공통으로 따르는 사실

| 항목 | 사실 |
|---|---|
| 추적 | 없음. 광고 SDK, 광고 식별자, 데이터 브로커 없음 |
| 광고 | 없음 |
| 결제 | 없음 |
| 위치, 연락처, 사진, 카메라, 마이크 | 수집하지 않음 |
| 전송 중 암호화 | 예. 모든 통신이 HTTPS |
| 삭제 | 앱 안: 설정 → 계정 삭제. 웹: [계정 삭제 요청 웹페이지 URL] |
| 처리 위탁 | Supabase(서버, 저장, 인증), Google Gemini API(AI 응답), [SMTP 제공자](인증 메일), Expo(앱 업데이트 배포), Sentry(오류 수집 도구를 쓰는 경우) |
| 알림 | 기기 로컬 알림. 푸시 토큰을 서버로 보내지 않음 |
| 앱 업데이트 | `expo-updates`가 앱을 열 때 Expo 서버에 운영체제 종류, 앱 버전, 업데이트 채널, 설치마다 만든 임의 식별값(`EAS-Client-ID`)을 보냄 |

오류 수집 도구(Sentry)는 `EXPO_PUBLIC_SENTRY_DSN`을 넣은 빌드에서만 켜집니다. 그 빌드를 제출하면 아래 표의 "Sentry를 쓰는 경우" 줄을 함께 답합니다.
`src/lib/report.ts`는 `sendDefaultPii: false`로 켜고 `setUser`를 부르지 않습니다. 확인했습니다.
남은 위험: Sentry 기본 설정은 오류 직전의 네트워크 요청 주소를 함께 보낼 수 있습니다. 앱의 요청 주소에 목표 ID가 들어갑니다. 운영자는 이 값으로 계정을 찾을 수 있어 "사용자와 연결 아니요"가 틀릴 수 있습니다. 요청 주소를 지우는 설정을 넣거나, 넣지 않으면 진단 줄을 "사용자와 연결 예"로 답합니다. `[앱 변경 필요]`

## 1. App Store 개인정보 라벨

App Store Connect → 앱 개인정보 보호에서 답합니다.

### 1.1 첫 질문

| 질문 | 답 |
|---|---|
| 이 앱에서 데이터를 수집합니까? | 예 |
| 추적에 사용되는 데이터가 있습니까? | 아니요 |

### 1.2 데이터 유형별 답

| 데이터 유형 | 해당 데이터 | 사용 목적 | 사용자와 연결 | 추적 |
|---|---|---|---|---|
| 연락처 정보 > 이메일 주소 | 가입 이메일 | 앱 기능 | 예 | 아니요 |
| 식별자 > 사용자 ID | 계정 ID | 앱 기능 | 예 | 아니요 |
| 식별자 > 기기 ID | 앱 업데이트 확인에 쓰는 설치별 임의 식별값(Expo) `[가정]` | 앱 기능 | 아니요 | 아니요 |
| 사용자 콘텐츠 > 기타 사용자 콘텐츠 | 목표 이름, 처음 이유, 학습 상황, 오늘의 이유, 목표 설정 대화, 학습 대화, 복습 답, 회고, 반성문 채팅, AI 응답 신고(메시지, 사유, 시각) | 앱 기능 | 예 | 아니요 |
| 사용 데이터 > 제품 상호작용 | 학습 시간, 회고 시간, 하루 완료 상태, 쿠폰, 연속 기록, 포기와 이용 정지 상태, 배운 표현과 복습 결과 | 앱 기능 | 예 | 아니요 |
| 진단 > 성능 데이터 | AI 사용 기록(토큰 수, 응답 시간, 성공 여부) | 앱 기능 | 예 | 아니요 |
| 기타 데이터 > 기타 데이터 유형 | 기기 시간대 | 앱 기능 | 예 | 아니요 |
| 진단 > 충돌 데이터 | 오류 내용. Sentry를 쓰는 경우만 | 앱 기능 | 아니요 | 아니요 |
| 진단 > 기타 진단 데이터 | 기기 모델, 운영체제 버전, 앱 버전. Sentry를 쓰는 경우만 | 앱 기능 | 아니요 | 아니요 |

판단 근거:
- 대화 내용은 "이메일 또는 문자 메시지"가 아닌 "기타 사용자 콘텐츠"로 답합니다. 이용자끼리 주고받는 메시지가 없고, AI와의 학습 대화입니다. `[가정]`
- AI 사용 기록과 포기 확정 횟수로 남용과 재가입 악용을 막는 일은 Apple 정의상 "앱 기능"에 들어갑니다. 앱 기능에는 사기 방지와 보안 조치가 포함됩니다.
- 분석, 개발자 광고, 제3자 광고, 개인화 목적은 고르지 않습니다. 분석 SDK가 없고, 학습 내용을 바꾸는 것은 이용자가 정한 목표에 따른 앱 기능입니다.
- Google Gemini API는 운영자를 대신해 처리하는 수탁자입니다. 수탁자가 받는 데이터도 위 표에 이미 들어 있습니다.

### 1.3 수집하지 않는다고 답하는 유형

건강 및 피트니스, 금융 정보, 위치, 민감한 정보, 연락처, 검색 기록, 탐색 기록, 구입 항목, 사진 또는 비디오, 오디오 데이터, 게임플레이 콘텐츠, 고객 지원 데이터, 광고 데이터, 이름, 전화번호, 물리적 주소.

## 2. Google Play 데이터 보안 양식

Play Console → 앱 콘텐츠 → 데이터 보안에서 답합니다.

### 2.1 개요 질문

| 질문 | 답 |
|---|---|
| 필수 사용자 데이터 유형을 수집하거나 공유합니까? | 예 |
| 수집한 모든 사용자 데이터가 전송 중에 암호화됩니까? | 예 |
| 계정을 만드는 방법 | 사용자 이름과 기타 인증(이메일과 일회용 인증번호) |
| 계정 삭제를 요청하는 웹 링크 | [계정 삭제 요청 웹페이지 URL] |
| 계정 없이 일부 데이터 삭제를 요청할 수 있습니까? | 아니요. 데이터는 계정에 묶여 있습니다 |
| 데이터 삭제 요청 방법을 제공합니까? | 예. 앱 안 계정 삭제와 웹 요청 |
| 독립적인 보안 검토를 받았습니까? | 아니요 |
| 가족 정책 준수 | 해당 없음. 13세 미만 대상이 아닙니다 |

### 2.2 데이터 유형별 답

"공유"는 아니요입니다. Google Play 정의상 운영자를 대신해 처리하는 수탁자(Supabase, Google Gemini API, SMTP 제공자, Expo, Sentry)로의 전송은 공유가 아닙니다.
수탁자에게 보내는 데이터도 "수집"으로 답합니다.

| 분류 > 유형 | 해당 데이터 | 수집 | 공유 | 임시 처리 | 필수 여부 | 목적 |
|---|---|---|---|---|---|---|
| 개인 정보 > 이메일 주소 | 가입 이메일, 삭제 뒤 남기는 이메일 해시 | 예 | 아니요 | 아니요 | 필수 | 앱 기능, 계정 관리, 사기 방지와 보안 및 규정 준수 |
| 개인 정보 > 사용자 ID | 계정 ID | 예 | 아니요 | 아니요 | 필수 | 앱 기능, 계정 관리 |
| 개인 정보 > 기타 정보 | 기기 시간대 | 예 | 아니요 | 아니요 | 필수 | 앱 기능 |
| 기기 또는 기타 ID > 기기 또는 기타 ID | 앱 업데이트 확인에 쓰는 설치별 임의 식별값(Expo) `[가정]` | 예 | 아니요 | 아니요 | 필수 | 앱 기능 |
| 메시지 > 기타 인앱 메시지 | 목표 설정 대화, 학습 대화, 회고, 반성문 채팅 | 예 | 아니요 | 아니요 | 필수 | 앱 기능 |
| 앱 활동 > 기타 사용자 제작 콘텐츠 | 목표 이름, 처음 이유, 학습 상황, 오늘의 이유, 복습 답, AI 응답 신고(메시지, 사유, 시각) | 예 | 아니요 | 아니요 | 필수(신고는 선택) | 앱 기능 |
| 앱 활동 > 앱 상호작용 | 학습 시간, 회고 시간, 하루 완료 상태, 배운 표현과 복습 결과 | 예 | 아니요 | 아니요 | 필수 | 앱 기능 |
| 앱 활동 > 기타 작업 | 쿠폰, 연속 기록, 포기 신청과 확정, 이용 정지 상태 | 예 | 아니요 | 아니요 | 필수 | 앱 기능, 사기 방지와 보안 및 규정 준수 |
| 앱 정보 및 성능 > 진단 | AI 사용 기록(토큰 수, 응답 시간, 성공 여부) | 예 | 아니요 | 아니요 | 필수 | 앱 기능, 사기 방지와 보안 및 규정 준수 |
| 앱 정보 및 성능 > 비정상 종료 로그 | 오류 내용. Sentry를 쓰는 경우만 | 예 | 아니요 | 아니요 | 필수 | 앱 기능 |
| 앱 정보 및 성능 > 기타 앱 성능 데이터 | 기기 모델, 운영체제 버전, 앱 버전. Sentry를 쓰는 경우만 | 예 | 아니요 | 아니요 | 필수 | 앱 기능 |

판단 근거:
- 대화는 "기타 인앱 메시지"입니다. Google 정의가 채팅 내용을 이 유형의 예로 듭니다.
- 기기 시간대를 넣을 유형이 따로 없어 "개인 정보 > 기타 정보"로 답합니다. 위치는 아닙니다. `[가정]`
- 이메일 해시는 계정 삭제 뒤 재가입 악용을 막는 데 씁니다. 그래서 이메일 주소의 목적에 "사기 방지와 보안 및 규정 준수"를 더합니다.
- 광고 ID, 위치, 연락처, 사진, 오디오, 금융 정보, 건강 정보, 웹 탐색 기록은 수집하지 않는다고 답합니다. 광고 ID 권한은 `app.json`의 `blockedPermissions`로 막았습니다.
- 앱 업데이트 확인 식별값은 기기 하드웨어 ID가 아니라 앱을 설치할 때 만든 임의 값입니다. 그래도 기기 밖으로 나가므로 "기기 또는 기타 ID"로 답합니다. `[가정]`
- AI 응답 신고(`message_reports`)는 "앱 활동 > 기타 사용자 제작 콘텐츠"에 넣습니다. 신고는 이용자가 고를 때만 생깁니다.

## 3. 처리방침과 맞춰 볼 곳

| 처리방침 | 이 파일 |
|---|---|
| 2.1 이용자가 직접 입력하는 항목 | 1.2, 2.2의 이메일, 사용자 콘텐츠, 메시지 |
| 2.2 서비스 이용 중 만들어지는 항목 | 1.2, 2.2의 사용자 ID, 제품 상호작용, 진단, 시간대 |
| 2.3 수집하지 않는 항목 | 1.3과 2.2의 "수집하지 않는다고 답함" |
| 3.2 계정 삭제 뒤 남기는 정보 | 2.2 이메일 주소 목적 |
| 6 처리 위탁, 7 국외 이전 | 0절 처리 위탁, 2.2 공유 판단 |

처리방침 2.2의 접속 기록(IP 주소)은 서버 운영사와 Expo가 남기는 로그입니다. 운영자가 따로 저장하거나 쓰지 않아 두 양식의 데이터 유형에 넣지 않았습니다. `[법무 확인]`
목표 설정 대화는 서버에 저장하지 않지만 Google로 보내므로 수집으로 답합니다.
