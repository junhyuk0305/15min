# 상황 대화에서 도움을 줄이고 다시 말하게 하기

## 1. W07의 핵심은 오류 개수와 도움의 양을 따로 조절하는 것

W07 4쪽은 정답을 바로 주는지, 오류를 한꺼번에 고치는지, 맞는 문장까지 고치는지를 점검하게 한다. 서비스에서도 교정을 많이 제공한다는 이유만으로 좋은 피드백이라고 판단하면 안 된다. 사용자가 상황에 맞게 답했다면 대화를 진행해야 한다.

7~13쪽의 출력, 상호작용, noticing 논의는 학습자의 다음 발화를 중요하게 다룬다. 우리 서비스에서는 오류 구간 하나를 짚고 다음 상황 질문에 다시 적용하게 한다. 다만 화면에 단서를 보여 줬다는 사실만으로 학습자가 차이를 알아차렸다고 확정할 수 없다.

14~15쪽의 error와 mistake 구분은 반응을 보고 판단하라는 취지다. 저장된 학습 이력만으로 “알지만 실수했다”고 진단하지 않는다. 이력은 어느 정도의 도움부터 시작할지 정하는 참고 자료로 사용한다.

| W07 쪽 | 이론과 관찰 | 서비스 결정 |
| --- | --- | --- |
| 9~12, 22~23 | 필요에 따른 도움 확대와 축소 | 배운 표현은 단서 우선, 같은 목표 재실패 시 패턴 |
| 13, 25 | 자기 발화와 목표 형태의 차이에 주목 | 실제 오류 구간과 구체적인 규칙 단서 |
| 16~18 | 여섯 피드백 유형, 고정 순서 없는 도움 분류 | 여섯 단계를 강제하지 않는 두 단계 정책 |
| 19~21 | 피드백 반응과 수정 성공의 구별 | 반응, 도움받은 적용, 지연 성과의 분리 |
| 24~26 | 수준과 과제에 따른 도움 선택 | 상황 흐름 유지, 한 번에 교정 목표 하나 |

**“한 번에 한 목표”와 “단서 후 패턴”은 이 서비스의 설계 선택이다.** 강의 자료가 모든 학습자에게 최적 오류 수나 단서 횟수를 증명한 것은 아니다. 원자료의 일기 수정 활동을 상황 대화에 맞춰 조정했다.

## 2. 원연구는 다시 말할 기회를 지지하지만 즉시 성공을 습득으로 보지 않는다

Schmidt는 입력의 특정 형태를 알아차리는 noticing이 학습으로 이어지는 과정에서 중요하다고 제안했다. 이론적 논증을 앱의 효과 검증으로 읽으면 안 된다. 여기서는 “전체 문장을 고쳐 보여 주기”보다 “실제 오류 부분을 짚기”의 근거로 사용했다. ([Schmidt, 1990](https://nflrc.hawaii.edu/PDFs/SCHMIDT%20The%20role%20of%20consciousness%20in%20second%20language%20learning.pdf))

Mackey는 교실 피드백, 학습자가 보고한 noticing, 의문문 발달 사이의 관계를 조사했다. 결과는 긍정적이지만 단순한 일대일 관계는 아니었다. 따라서 한국어 단서를 출력했다는 로그를 noticing 측정값으로 사용할 수 없다. ([Mackey, 2006](https://research.lancaster-university.uk/en/publications/feedback-noticing-and-instructed-second-language-learning/))

Lyster와 Ranta의 교실 관찰에서는 유도와 규칙 단서 등이 교사가 고쳐 말하는 recast보다 학습자 자신의 즉시 수정으로 이어지는 경우가 많았다. 이후 교실 연구 메타분석에서도 교정 피드백의 효과가 보고됐고 prompts의 효과가 recasts보다 컸다. 이것이 recast를 금지하거나 모든 순간에 단서만 주라는 뜻은 아니다. 교실 구어 연구를 LLM 텍스트 역할극에 그대로 일반화할 수도 없다. ([Lyster & Ranta, 1997](https://www.researchgate.net/publication/252160472_CORRECTIVE_FEEDBACK_AND_LEARNER_UPTAKE_Negotiation_of_Form_in_Communicative_Classrooms), [Lyster & Saito, 2010](https://kazuyasaito.net/SSLA2010.pdf))

Lai와 Zhao의 소규모 연구에서는 대면 과제보다 텍스트 채팅에서 자기 오류 noticing이 더 많이 관찰됐다. 텍스트 대화는 자기 발화를 다시 볼 수 있다는 장점이 있다. 이 결과만으로 LLM 대화가 장기 습득이나 발음 개선에 효과적이라고 말할 수는 없다. ([Lai & Zhao, 2006](https://hub.hku.hk/handle/10722/175414))

한국어 모어 EFL 연구를 분석한 Schenck는 피드백 효과가 목표 문법의 특성과 학습 조건에 따라 달라진다고 보고했다. 이번 정책도 처음 배우는 항목까지 단서만으로 추측하게 하지 않는다. 알려진 항목과 새 항목을 구분하는 것은 이 결과를 서비스에 적용한 추론이다. ([Schenck, 2020](https://link.springer.com/article/10.1186/s40862-020-00097-9))

2026년 피드백 시점 재현연구에서는 과제 사이 피드백이 지연 피드백보다 즉시 명시지식 검사에서 우세했지만, 2주 후에는 집단 차이가 유지되지 않았다. 피드백 직후 연습 기회와 평가 시점을 함께 봐야 한다. 이번 변경은 대화 중 짧은 지원을 유지하며, 모든 오류를 언제나 즉시 교정하는 정책으로 확대하지 않는다. ([Li 외, 2026](https://onlinelibrary.wiley.com/doi/10.1111/lang.70019))

AI 학습에서는 도움을 받는 동안의 성과와 도움을 제거한 뒤의 성과가 다를 수 있다. Bastani 등의 수학 현장 실험에서 일반형 AI 사용 집단의 무AI 시험 성과 저하는 튜터 보호 지침으로 대부분 완화됐다. 그러나 보호 지침을 둔 튜터가 대조 집단보다 시험 성과를 높였다는 증거는 없었다. 영어학습에 대한 직접 증거는 아니지만, 도움받은 답을 학습효과로 집계하지 말아야 할 이유다. ([Bastani 외, 저자 공개 원문](https://hamsabastani.github.io/education_llm.pdf))

Karpicke와 Roediger의 단어쌍 실험은 지연 기억을 평가할 때 반복 회상의 중요성을 보여 준다. 이 연구를 대화 능력 전반의 근거로 확대하지 않는다. 우리 서비스에서는 당일 적용과 이후 회상 결과를 분리해 해석하는 데 사용했다. ([Karpicke & Roediger, 2008](https://learninglab.psych.purdue.edu/downloads/2008/2008_Karpicke_Roediger_Science.pdf))

## 3. 두 전문가의 반론을 거쳐 ‘배운 목표에만 단서 우선’으로 좁힘

영어교육 전문가의 최초 제안은 첫 오류에 단서를 주고 다시 실패할 때 패턴을 보여 주는 방식이었다. AI 학습설계 전문가는 `knownItems`에 단순 노출 상태인 `seen`도 포함된다는 점을 지적했다. 문자열을 본 이력만으로 자기수정할 지식이 있다고 가정할 수 없다는 반론이었다.

합의: **단서 우선 자격을 `taught`, `used`, `recalled`로 제한했다.** `seen`만 있는 표현과 새 표현은 패턴을 먼저 제공한다. 이 상태도 숙달을 뜻하지 않는다. 학습자에게 알고도 틀렸다는 설명을 붙이지 않는다.

AI 학습설계 전문가는 다른 질문에 답하는 행동을 고전적인 repair와 동일시할 수 없다고 지적했다. 영어교육 전문가는 상황 대화의 목적상 원문 반복보다 새 내용에 적용할 기회를 유지하는 편이 적절하다고 보았다.

합의: 기존의 내용이 다른 질문 규칙을 유지한다. 그 직후의 성공은 **도움받은 적용**으로 해석한다. 같은 문장을 직접 수정한 성공이나 새로운 상황으로의 장기 전이로 부르지 않는다.

영어교육 전문가는 같은 목표에서 다시 실패했는지 대화 요약만으로 추정하지 말자고 제안했다. AI 학습설계 전문가는 목표 표현과 도움 단계를 메시지 메타데이터로 남기는 최소 구현에 동의했다. 동의어로 목표를 바꿔 단서 단계가 반복되는 문제를 줄이기 위해 기존 목표 키를 재사용하도록 지시한다.

합의: 자연스러운 대안 표현은 통과시킨다. 목표 표현이 없으면 해당 표현의 사용 성공으로는 기록하지 않는다. 상황에서 의사소통을 잘한 것과 특정 표현을 산출한 것을 구분한다.

이번 두 페르소나는 설계와 검토에 사용했다. 실행 중 두 모델이 매 턴 토론하는 기능은 추가하지 않았다. 그 방식의 추가 비용과 응답 지연이 학습 이익으로 이어진다는 근거가 없기 때문이다.

## 4. 프롬프트뿐 아니라 표시와 학습 기록까지 연결

기존 로직은 교정 판정에 패턴 모달을 요구했다. 원어민이 다르게 표현할 법한 문장까지 교정 대상으로 해석할 여지도 있었다. 변경 후 프롬프트는 실제 오류와 단순한 표현 선호를 구분한다. 의미 전달을 막는 오류, 현재 과제의 목표 형태, 되풀이되는 오류 중 하나에 집중하도록 지시한다.

| 입력 조건 | 표시와 다음 행동 | 기록 |
| --- | --- | --- |
| 상황에 맞는 짧은 답 또는 자연스러운 대안 | 교정 없이 대화 진행 | 해당 목표가 실제 포함된 경우에만 사용 후보 |
| 새 표현 또는 `seen`만 있는 표현의 오류 | 패턴 모달과 짧은 안내 | 패턴 도움 이력 |
| 배운 표현의 첫 오류 | 모달 숨김, 실제 오류 부분을 짚는 한국어 단서 | 목표와 `cue` 단계 |
| 최근 도움과 같은 목표에서 재실패 | 패턴 모달 표시 | 같은 목표와 `pattern` 단계 |
| 단서 뒤 자연스럽게 목표 표현 사용 | 다음 질문 진행 | `used`, 최근 지원이 있으면 `aided: true` |
| 오답, 한국어 혼용, 역할 이탈 속 목표 문자열 | 사용 성과 승격 제외 | `used` 생성 제외 |

새 항목 예산은 기존 제한을 유지한다. 새 패턴을 보여 줄 예산이 없으면 모달을 줄이고 구체적인 코치 단서로 이어 간다. 이때 같은 새 목표를 계속 요구하지 않고 기존 언어나 짧은 답으로 가능한 쉬운 상황 질문을 허용한다. 새 표현을 곧바로 가르치는 기본 정책의 예외다. 이 의미 판단을 서버가 보장하지는 못하므로 실제 모델 평가가 필요하다.

예시: 카페에서 학습자가 “I want order a latte.”라고 답했다. `I want to …`를 처음 배우는 경우에는 해당 패턴과 사용 설명을 보여 준다. 완성 교정문 “I want to order a latte.”를 그대로 제시하지 않는다.

같은 패턴을 이미 가르쳤다면 첫 오류에서는 “'want order'에서 두 동사를 잇는 말을 확인하십시오.” 같은 단서만 제공한다. 상대는 “And which snack would you like?”처럼 주문 내용을 바꾼 질문으로 다음 적용 기회를 만든다. 학습자는 음료 대신 간식을 주문하며 같은 패턴을 사용할 수 있다. 이 질문은 목표 패턴을 직접 제시하지 않지만 앞선 코치 단서가 있으므로 뒤의 성공은 도움받은 적용이다.

같은 목표에서 다시 “I want order a muffin.”이라고 답하면 패턴 도움을 늘린다. “I'd like a muffin.”처럼 다른 자연스러운 표현으로 답하면 대화를 진행한다. 특정 패턴을 강요하려고 정답을 오답 처리하지 않는다. 위 대사는 동작 설명용 예시이며 실제 모델 호출 결과가 아니다.

변경 파일: [프롬프트](../supabase/functions/_shared/prompts/lesson-turn.ts)는 대안 허용, 한 목표 교정, 구체적인 단서, 같은 목표의 새 질문을 지시한다. 모델은 패턴 후보를 생성하고 서버가 학습 이력에 따라 표시 여부를 정한다. 단서만 보여 줄 때는 후보 모달을 숨긴다.

[서버 판정](../supabase/functions/lesson-turn/core.ts)은 단서와 패턴 단계를 결정한다. 완성 교정문 노출 검사에 상대 대사를 포함한다. [메시지 처리](../supabase/functions/lesson-turn/handler.ts)는 목표와 도움 이력을 저장한다. 최근 코치 단서와 모달, 상대 대사의 목표 표현 노출을 도움받은 사용 판정에 포함한다.

사용 기록은 `natural` 판정 뒤에만 생성하도록 제한했다. 정확한 표현 하나를 썼더라도 문장 다른 부분에 오류가 있으면 기록을 놓칠 수 있다. 현재 항목별 정확도를 별도로 채점하지 않는 조건에서 오답을 성취로 올리지 않기 위한 보수적 선택이다.

DB 테이블과 화면은 추가하지 않았다. 기존 코치 안내, 모달, 메시지 메타데이터를 사용한다. 기존 SRS와 복습 간격 계산은 이번 변경 범위에 포함하지 않았다.

## 5. 코드 검증과 실제 학습효과 검증을 분리

**자동 검증 결과: 앱 테스트 258/258, 함수 테스트 70/70, lint와 typecheck 통과.** 함수 테스트에는 [피드백 회귀 테스트](../supabase/functions/tests/feedback.test.ts) 11개가 포함된다. 배운 표현의 단서 우선, `seen` 예외, 동일 목표의 도움 확대, 상대 대사의 완성답 유출, 단서 뒤 도움받은 사용, 오답의 사용 승격 제외를 확인했다. 평가 스크립트의 Deno 타입 검사도 통과했다.

독립 검토에서는 단서 이후 한국어 답변이 두 턴 이어진 다음 성공하면 도움받은 사용 이력이 빠지는 사례를 발견했다. 해당 기록 처리를 수정하고 회귀 테스트로 확인했다. `AI_FAKE` 평가의 14개 gate도 통과했다. 이 결과는 평가 실행 경로와 고정 응답 처리의 검사이며 실제 모델의 교육 품질을 증명하지 않는다.

모델 API 키를 사용할 수 없어 실제 모델 응답에 대한 품질 평가는 수행하지 않았다. 합성 응답을 넣는 서버 테스트는 단계 전환과 기록 처리를 검사한다. 자연스러운 대안을 실제 모델이 받아들이는지, 단서가 충분히 구체적인지, 다음 질문이 같은 목표의 사용을 유도하는지는 별도 모델 평가가 필요하다.

교육용 LLM 평가는 한 개의 유용성 점수보다 오류 식별, 지도, 답안 노출 등 구체적인 행동으로 나누는 편이 검토에 유리하다. MRBench도 여러 교육 행동 축으로 평가한다. 다만 수학 대화 벤치마크의 타당도가 영어 상황 대화에 자동으로 적용되지는 않는다. ([Maurya 외, 2025](https://aclanthology.org/2025.naacl-long.57.pdf))

후속 모델 평가에서는 동일 입력과 동일 모델 설정으로 변경 전후를 비교한다. 짧은 정답의 과잉 교정, 새로운 표현의 직접 지도, 배운 표현의 단서, 같은 목표 재실패, 다른 자연스러운 답 허용, 예산 소진, 답안 유출을 각각 확인한다. 다음 질문의 상황 적합성과 단서 품질은 영어교육 검토자가 표본을 읽어 확인한다.

**사용자 파일럿은 제안 단계이며 구현하거나 실행하지 않았다.** 소규모 탐색에서는 같은 학습자에게 난도가 비슷한 목표 두 묶음을 배정할 수 있다. 한 묶음에는 기존 패턴 우선, 다른 묶음에는 단서 우선을 적용한다. 목표 묶음과 순서를 교차 배정하고 수준, 연습량, 순서 효과를 함께 기록한다. 학습자가 한 조건에서 익힌 전략을 다른 조건에도 쓰는 오염 가능성은 남는다.

| 평가 시점 | 확인할 결과 | 해석 범위 |
| --- | --- | --- |
| 피드백 직후 | 도움 뒤 목표 표현 적용, 과잉 교정, 교정 중 이탈 | 지도 적절성과 즉시 적용 |
| 2~3일 후 | 답안과 패턴을 숨긴 첫 응답 | 지연 수행의 탐색적 관찰 |
| 같은 지연 평가의 새 장면 | 새로운 내용에서 의미 전달, 목표 형태의 정확한 산출 | 전이의 탐색적 관찰 |

2~3일 간격은 파일럿 운영을 위한 제안이다. 연구가 이 앱의 최적 간격을 확정한 것은 아니다. 표본 규모와 확증 실험 설계는 파일럿의 변동성과 효과 크기를 보고 정해야 한다.

기존 복습 A에는 한국어 의미와 지정 표현 단서가 있다. 이를 일반적인 무단서 전이 검사로 부르지 않는다. 새 장면에서 목표 표현을 쓰지 않은 자연스러운 답도 의사소통 성공으로 따로 평가해야 한다.

남은 한계: 자연스러움 판정과 교정 목표 선택은 여전히 모델에 의존한다. 문자열 기반 답안 노출 검사는 의미가 같은 바꿔 말하기를 모두 잡지 못한다. 최근 지원 이력의 범위도 학습자가 기억하는 모든 도움을 표현하지 못한다. 따라서 `used`는 관찰된 사용이고 `aided`는 기록된 최근 도움 여부다. 둘 다 숙달 판정으로 사용할 수 없다.

다음 판단 기준은 교정량 증가가 아니다. 같은 상황 목표를 유지하면서 도움을 덜 받아도 적절하게 답하는지가 기준이다. 이번 구현은 그 비교를 할 수 있도록 피드백 단계와 사용 기록의 혼동부터 줄인다.
