# 그래고 UX 갭 분석 (실서비스 앱 기준)

- 기준: `feat/mvp-launch` 271c119. 스크린샷은 `docs/화면상태/*.png`(10-18 13:31 촬영, 현재 코드와 같음), `docs/시나리오/`, 첫 사용 워크스루 `shots-frw/`(10-18 11:57, 신고 버튼이 "!" 아이콘이던 이전 빌드).
- 비교 대상: Duolingo, Speak, 토스, Notion 수준의 iOS/Android 앱 관례.
- 우선순위: **P0** 없으면 "진짜 앱" 느낌이 안 남. **P1** 출시 품질. **P2** 다듬기.
- 읽기 전용 분석이다. 저장소 파일은 고치지 않았다.

## 0. 먼저 알아 둘 사실

1. **앱 전체에 애니메이션이 사실상 없다.** `Animated`는 홈 독촉 깜빡임(`(tabs)/index.tsx:80-94`) 한 곳뿐이다. `react-native-reanimated` 4.5.1은 설치만 돼 있고 쓰는 곳이 없다. 모달 3개는 `animationType="fade"`다.
2. **햅틱은 딴짓 팝업 한 곳뿐이다**(`useLearnClock.ts:58`). `expo-haptics`는 이미 설치돼 있다.
3. **스크린샷은 모두 웹 빌드다.** 웹 스택은 화면 전환 애니메이션과 iOS 스와이프 뒤로를 보여 주지 않는다. 네이티브 스택은 기본 push 애니메이션이 있다. 오너가 웹 미리보기로 판단했다면 체감이 실제보다 나쁘다. 개발 빌드(실기기)로 다시 확인해야 한다. exact-alarm 네이티브 모듈이 있어 Expo Go로는 안 된다.
4. **헤더가 있는 화면이 하나도 없다.** 루트 `Stack`이 `headerShown: false`(`_layout.tsx:285`)이고, 탭도 `headerShown: false`다. 뒤로 가기는 모두 밑줄 글자 버튼이다.
5. **처음 한 번 보여 주는 안내 장치가 없다.** 저장되는 플래그는 `onboarded` 하나다(`store.ts:54, 484`). 화면구성.md의 "O6 학습 방식(채팅 예시 애니메이션)"은 구현되지 않았다. 첫 학습 날 A, B, C 단계와 시간 규칙을 미리 알려 주는 곳이 없다.
6. 개발용 "DEV TIME SHIFT"는 이미 `__DEV__`일 때만 `require`된다(`settings.tsx:16-18`). 프로덕션 번들에는 안 들어간다. 스크린샷에만 보인다.

### 빨강 검증 문구 충돌 (오너 결정 필요)

- 오너 요청: "N자 더 쓰십시오." 같은 검증 문구를 빨강으로.
- 화면구성.md 9행: "빨강은 독촉 상태와 포기 흐름에만 쓴다. 평소 화면에 쓰지 않는다."
- 그런데 `docs/design-system.html` 248행은 이미 "글자 수 미달, 입력 오류: 빨강 작은 글자"를 허용한다. `theme.ts`의 `redText` 주석도 "미달, 오류"를 적었다.
- 지금 코드도 이미 섞여 있다. 글자 수 카운터 `8/20`은 빨강(`ui.tsx` Field), 오류 문장(`ErrorLine`)과 "오답"은 빨강이다. 버튼 위 이유(`disabledReason`)만 회색(`ui.tsx:179`)이다.
- 권장: 빨강은 **사용자가 입력을 시작했는데 아직 모자랄 때만** 쓴다. 비어 있을 때의 안내("이메일을 입력하십시오.", "답을 쓰면 누를 수 있습니다.")는 오류가 아니다. 회색으로 두거나 아예 없앤다. 빈 칸에 처음부터 빨강을 띄우면 꾸지람처럼 보이고 독촉 빨강의 무게가 떨어진다.
- 결정되면 화면구성.md 9행과 `theme.ts` 1행 주석을 design-system.html에 맞춰 고치고 결정로그에 남긴다.
- 빨강 바탕(독촉, 포기)과 다크(B) 위에서는 각각 `onRed`, dark `redText #FF6F61`을 쓴다. 지금 `useInk().alert`가 이미 처리한다.

- 한 화면에 안내는 한 번에 하나만 띄운다. 겹치면 다음 방문으로 미룬다.
- 학습 시계가 도는 동안에는 코치마크를 띄우지 않는다. 띄워야 하면 시계를 멈춘다(기획서 11.2).
- 규칙을 알리는 4번만 건너뛰기를 두지 않는다. 나머지는 모두 건너뛸 수 있다.
- 설정에 "안내 다시 보기" 줄을 둔다(P2).
- 저장: `store.ts`의 `partialize`에 `seenTips: string[]`를 더한다. 계정이 아니라 기기 기준이어도 된다.
- 코드: 코치마크 공통 부품(대상 위치를 `measureInWindow`로 재서 구멍 뚫린 덮개 + 말풍선), `src/components/` 아래. 문구는 `copy.ts`.

## 6. 채팅 경험 (학습 B, 목표 정하기, 회고, 반성문)

### C1. 세 채팅이 서로 다르다
- 목표 정하기: 입력창 + 오른쪽 "보내기" 버튼, 위에 회색 안내, 코치 줄 아래 "신고" 밑줄 (goal-new-normal-chat.png).
- 학습 B, 회고: 같은 Composer, 신고는 줄 오른쪽 (learn-b-normal.png, retro-normal-chat.png).
- 반성문: 입력창 아래 폭 전체 주 버튼 "보내기", 그 아래 계정 삭제와 약관 (suspended-normal.png).
- 권장: Composer 하나로 통일한다. 우선 P0. 코드 `learn/parts.tsx` Composer를 `src/components/`로 옮겨 세 곳이 함께 쓴다.

### C2. 글자 단위 표시 (오너 요청)
- 서버는 완성된 문장을 한 번에 준다. 표시만 단어(어절) 단위로 나눈다. 진짜 스트리밍은 필요 없다.
- 속도: 어절당 30~40ms. 메시지 하나가 1.5초를 넘으면 속도를 올려 1.5초에 맞춘다. 코치 표현 카드(표현, 뜻, 단어)는 글자 표시가 끝난 뒤 200ms 페이드인한다.
- 화면 아무 곳이나 누르면 즉시 전체를 보인다. 입력을 시작해도 즉시 끝낸다.
- 스크린리더는 처음부터 전체 문장을 한 번 읽는다(`accessibilityLabel`에 전체 문장).
- 다시 들어왔을 때 이미 본 메시지, 기록 상세, 과거 메시지에는 쓰지 않는다. 새로 도착한 마지막 메시지에만 쓴다.
- **시계 규칙 충돌(결정 필요):** 기획서 11.2는 AI가 응답을 만드는 동안 시간을 세지 않는다. 글자 표시 1.5초를 "응답 중"으로 볼지 정해야 한다. 권장: 표시가 끝날 때까지 시계를 멈춘 채로 둔다. 딴짓 2분 타이머도 표시가 끝난 뒤부터 센다. 이렇게 하면 사용자는 손해를 보지 않는다.
- 코치 모달(표현 설명 카드)에는 쓰지 않는다. 참고용 카드라 바로 읽혀야 한다.

## 10. 구현 순서 제안

1. **공통 부품 먼저** → 검증: 기존 스크린샷 대비 깨진 화면 0장
   - `theme.ts`에 모션 토큰 M, `useReducedMotion` 래퍼, 햅틱 래퍼(웹 무시).
   - `ui.tsx` Button, Row, Card 눌림 애니메이션. `TextButton` 밑줄 제거안. 공통 Header(chevron, 제목, 오른쪽 슬롯). 공통 BottomSheet.
2. **내비게이션** (N1~N10) → 검증: 모든 push 화면에 chevron, 강제 화면에 없음, Android 뒤로 동작표(MP 7.7-2) 다시 확인.
3. **채팅** (C1~C4, M7~M9) → 검증: 글자 표시 중 시계 멈춤, 딴짓 2분이 표시 끝부터 세는지 단위 테스트.
4. **학습 연출과 처음 안내** (M4, 3절 4, 6, 9번, F3) → 검증: 첫 학습일 시나리오 S3를 실기기에서 다시 찍기.
5. **설정 재설계** (7절) → 검증: 목표 없음, 알림 꺼짐, 정확한 알람 거부 3상태 스크린샷.
6. **성공 순간과 피드백** (F9, F10, F11, 토스트, 당겨서 새로고침).
7. **나머지 P1, P2.**

각 단계 끝에 `npx expo lint`, `npx tsc --noEmit`, `npm run check:static`(한국어는 `copy.ts`에만), 화면상태 재촬영. 웹 촬영은 모션을 보여 주지 못하므로 실기기 개발 빌드 화면 녹화를 함께 남긴다.

## 11. 오너 결정이 필요한 것

1. 검증 문구 빨강 범위(1절). 화면구성.md 9행 갱신 여부.
