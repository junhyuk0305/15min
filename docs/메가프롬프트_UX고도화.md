# 그래고 UX 고도화 메가 프롬프트

## 0. 역할과 목표

너는 Duolingo, Speak, 토스 수준의 모바일 앱 UI/UX를 직접 만들어 본 시니어 모바일 엔지니어이자 인터랙션 디자이너다.
목표는 지금의 그래고 MVP를 실제 사용자가 막힘 없이 자연스럽게 쓰는 앱 수준으로 다듬는 것이다. 기능은 이미 있다. 이번 일은 움직임, 내비게이션, 처음 안내, 피드백, 채팅 경험, 설정 화면을 실서비스 앱처럼 만드는 것이다.

### 0.1 오너의 요청 (원문 요지)
1. 전체적으로 애니메이션을 넣는다.
2. 시간대 설정처럼 불필요한 것은 한국 시간에 맞춰 고정한다.
3. 뒤로 가기 버튼, 타이머, 처음 쓰는 사람에게 설명이 필요한 순서는 모달 등으로 설명한다. 일반적인 앱의 UI/UX 규칙을 따른다.
4. 설정 화면이 보기 어렵다. 일반 앱 설정처럼 다시 만든다.
5. 코치가 말할 때 AI 채팅처럼 한 단어씩 써지는 연출을 넣는다.
6. "20자 더 쓰십시오." 같은 안내 문구는 빨강으로 보인다.
7. 전반적으로 실제 앱처럼 개선한다.

### 0.2 완료의 정의
아래가 모두 참이어야 끝난다.
1. 5절의 단계 U0~U9를 모두 마치고, 각 단계의 "확인"을 증거와 함께 통과했다.
2. 6절 품질 기준을 통과했다. 기존 MVP 품질 기준(`docs/메가프롬프트_MVP출시.md` 7절)이 깨지지 않았다.
3. `docs/UX고도화_갭분석.md`의 P0 항목은 전부 반영했다. P1은 반영하거나 미반영 사유를 남겼다. 근거는 7.1의 대조표다.
4. 사용자 여정 S1~S17(`docs/시나리오검증.md`)이 다시 모두 통과한다.
5. 결과가 `feat/ux-polish` 브랜치에 단계별 커밋으로 있고, 오너가 `feat/mvp-launch`와 합칠 수 있게 정리돼 있다(8절).

실행하지 못한 것은 "미검증(사유)"로 보고한다. 끝났다고 쓰지 않는다.

## 1. 작업 규칙

### 1.1 묻지 않고 진행한다
- 사용자에게 질문하지 않는다. 모호하면 2절 우선순위와 3절 기본값으로 정한다. 정한 것은 `docs/결정로그.md`에 새 절 "## 3. UX 고도화 결정"을 만들어 한 줄씩 남기고 계속한다.
- 결정로그 형식: `날짜 | 항목 | 고른 것 | 근거 | 되돌리는 법`.
- 사람이 해야 하는 일(실기기 확인 등)을 만나면 멈추지 않는다. `docs/HANDOFF.md`에 새 절 "## 5. UX 고도화 뒤 사람 확인"을 만들어 추가하고 계속한다.

### 1.2 멈춰도 되는 경우는 셋뿐이다
1. 돈이 나가는 행동. 유료 플랜, 유료 API 대량 호출.
2. 스토어 제출, 공개 배포, 원격 저장소 push.
3. 사용자 데이터나 기존 커밋 이력을 지우는 행동. 로컬 DB를 `db reset` 하는 것도 포함한다.

### 1.3 기존 규칙
- `AGENTS.md`와 `~/.claude/CLAUDE.md`를 먼저 읽고 따른다.
- Expo 57 API는 기억으로 쓰지 않는다. `https://docs.expo.dev/versions/v57.0.0/`와 설치된 패키지 버전의 공식 문서를 확인한다. 버전 없는 Expo 문서는 이미 SDK 58 기준이라 틀릴 수 있다.
- 지난 세션에서 공식 문서로 확인한 SDK 57 메모가 `docs/Expo57_확인메모.md`에 있다(항목마다 출처 URL). 핵심 사실은 9.1에 옮겨 두었다. 메모에 없는 API는 문서를 다시 확인한다.
- 패키지는 `npx expo install`로만 추가한다. 여러 에이전트가 동시에 설치하지 않는다. 설치는 오케스트레이터가 한 번에 한다.
- 정책 숫자와 판정은 `src/lib/rules.ts`, 알림 계획은 `src/lib/plan.ts`, 문구는 `src/lib/copy.ts` 한 곳에 둔다. 한국어 문자열은 `copy.ts` 밖에 두지 않는다(`npm run check:static`이 검사한다).
- 화면 문구를 새로 쓰거나 고칠 때는 `copy-tone` 스킬을 먼저 불러온다. `docs/용어집.md`와 MVP 메가프롬프트 7.6 문구 규칙을 따른다.

### 1.4 git
- 시작하면 `feat/mvp-launch`의 최신 커밋에서 `feat/ux-polish` 브랜치를 만든다.
- 단계(5절)마다 커밋한다. 커밋 메시지 끝에 저장소 관례대로 Co-Authored-By 줄을 단다.
- `git add -A`를 쓰지 않는다. 바꾼 파일만 경로로 올린다.
- 아래는 사용자 작업물이다. 수정하지 않고 커밋에도 넣지 않는다: `docs/기획서.md`(수정 상태), `docs/*.html`, `docs/기획안_발표용.md`, `docs/메가프롬프트_MVP출시.md`, `docs/학습세션_결정안.md`, `docs/학습콘텐츠.md`. 예외: 마지막 단계에서 `WORK_LOG.md` 갱신.
- push하지 않는다. `feat/mvp-launch`에 merge, rebase하지 않는다. 합치는 것은 오너가 한다.

### 1.5 검증 게이트
단계마다 아래가 모두 통과해야 다음 단계로 간다.
```
npm run typecheck
npm run lint
npm test
npm run check:static
npx expo-doctor
npm run test:functions
npm run test:db
```
DB나 Edge Function을 건드리지 않은 단계도 마지막 두 개를 돌린다. 실패를 숨기지 않는다. 고칠 수 없으면 결정로그와 HANDOFF에 원인과 출력을 적는다.

### 1.6 에이전트를 적극적으로 쓴다
- 지난 세션처럼 오케스트레이터는 계약과 결정을 고정하고, 단계별로 에이전트에 나눠 맡기고, 결과를 검증하고 커밋한다.
- 병렬로 돌릴 때는 파일 소유를 먼저 나눈다. `copy.ts`, `store.ts`, `api.ts`, `ui.tsx`, `_layout.tsx`처럼 여럿이 고치는 파일은 키나 영역을 나누고, 고치기 직전에 다시 읽게 한다.
- 구현 에이전트는 커밋하지 않는다. 오케스트레이터가 게이트를 돌린 뒤 커밋한다.
- 수정 묶음이 끝날 때마다 구현 맥락을 주지 않은 독립 검증 에이전트(`verify`)를 돌린다. 지난 세션에서 수정 묶음이 치명적 회귀를 넣었고 독립 검증이 잡았다(9절).

## 2. 정본과 우선순위

충돌하면 위가 이긴다.
1. 이 프롬프트의 3절 기본값과 6절 품질 기준.
2. 오너 요청 0.1.
3. `docs/기획서.md` v9의 원칙과 정책. 특히 3절 원칙, 11.2 시간 규칙, 9절 말투.
4. `docs/결정로그.md`의 기존 결정. 이번 기본값과 충돌하면 이번 것이 이기고, 결정로그에 바뀐 것을 적는다.
5. `docs/메가프롬프트_MVP출시.md` 7절 품질 기준. 3절에서 예외로 정한 것만 바뀐다.
6. `docs/UX고도화_갭분석.md`와 `docs/UX고도화_영향지도.md`. 이번 작업의 근거 분석이다. 권장을 기본으로 따르되, 3절과 다르면 3절이 이긴다.
7. 화면 시각 기준 `docs/ia-screens.html`(웹소설 D안), `docs/design-system.html`. 색은 아이보리, 검정, 빨강을 유지한다.
8. 현재 코드.

| 다크 모드 | 기기 다크 모드를 따르지 않는다. 학습 B만 다크 | 기존 결정 |
| 개발 패널 | 프로덕션에서는 이미 빠진다. 개발 빌드에서도 설정 목록에서 빼고 "앱 버전"을 7번 눌러 여는 별도 화면으로 옮긴다 | 설정 화면 스크린샷과 리뷰를 깨끗하게 |

## 4. 설계 원칙

### 4.1 모션
- 공용 모듈 `src/lib/motion.ts` 하나에 시간, 곡선, 프리셋을 둔다. 값의 출발점: 빠름 120ms, 기본 200ms, 느림 320ms, 카운트업 800ms, 기본 곡선 ease-out cubic, 시트는 스프링(감쇠 20, 강성 220). 영향지도 B-6과 갭분석 5절을 따른다.
- Reanimated 4.5(설치됨)를 쓴다. 추가 babel 설정은 필요 없다(SDK 57 문서 확인됨). 웹에서 `springify`는 동작하지 않으니 웹에서는 시간 기반으로 대체한다.
- 줄인 움직임 설정을 지킨다. 켜져 있으면 이동, 확대, 흔들기, 카운트업, 글자 단위 표시, 깜빡임을 끄고 150ms 이하 페이드만 남긴다. 지금 홈 독촉 깜빡임은 이 설정을 무시하므로 고친다.
- 움직임은 의미가 있을 때만 쓴다. 상태 변화, 위치 이동, 결과 알림. 꾸미기용 반복 애니메이션은 넣지 않는다.
- 갭분석 5절 M1~M20 표가 위치별 목록이다. P0부터 넣는다.

### 4.2 햅틱
- `expo-haptics` 래퍼 하나를 두고 웹에서는 아무것도 하지 않는다. 갭분석 4절 햅틱 지도를 따른다.
- 독촉 알림 진동과 겹치지 않게 앱 안 햅틱은 표에 있는 순간에만 쓴다.

### 4.3 내비게이션과 화면 구조
- 공통 `Header`(높이 52, chevron 아이콘 24, 제목 `T.h2`, 스크롤하면 아래 hairline, 오른쪽 슬롯)를 `src/components/`에 둔다. Expo Router v57 `Stack` 헤더를 쓸지 공통 부품을 쓸지 하나로 통일하고 결정로그에 남긴다. 웹 스크린샷과 명조 제목 때문에 공통 부품이 단순할 가능성이 높다.
- 화면 전환 방향은 갭분석 N13을 따른다. 학습 시작은 아래에서 올라오는 몰입 전환, 완료 뒤 홈은 아래로 닫힘, 나머지는 오른쪽 push. 웹은 Stack 애니메이션을 지원하지 않으니 웹에서는 짧은 페이드로 대체한다.
- 탭바는 지금 JS 탭을 유지한다. 홈이 빨강 상태일 때 탭바와 상태 표시줄도 빨강으로 맞춘다.

### 4.4 채팅 경험
- 입력창(Composer)을 `src/components/`의 공용 부품 하나로 통일한다. 학습 B, 회고, 목표 정하기, 반성문이 같이 쓴다. 둥근 입력창 안 오른쪽에 원형 보내기 아이콘(접근성 이름 "보내기"), 한 줄에서 시작해 5줄까지 늘어남, 글자 수 조건이 있으면 안쪽 오른쪽 아래 카운터.
- 메시지 등장은 페이드와 8px 올라옴 220ms. 같은 화자 묶음 간격(4px, 14px)은 유지한다.
- 새 메시지가 오면 맨 아래로 스크롤한다. 사용자가 위로 올려 읽는 중이면 강제로 내리지 않고 "새 메시지" 알약 버튼을 띄운다.
- 반성문 화면은 새 메시지가 입력창에 가려지는 결함이 있다(갭분석 F13, P0). 계정 삭제와 약관 링크는 헤더 "⋯" 메뉴로 옮긴다.
- A, C 복습 답은 한 줄 입력으로 바꾸고 키보드의 보내기 키로 제출한다. 자동 대문자와 자동 고침을 끈다.

### 4.5 설정 화면
- 갭분석 7절 구조를 따른다. 묶음 카드(목표, 알림, 정보, 계정), 줄마다 현재 값과 오른쪽 화살표, 묶음 아래 회색 설명, 맨 아래 묶음 밖에 "계정 삭제하기" 빨강 글자 버튼.
- 알림 줄은 눌리면 시스템 설정으로 간다. 꺼짐이면 빨강 점. Android는 "정확한 시각 알림" 줄을 더한다(`getExactAlarm`, `openExactAlarmSettings`가 이미 있다).
- 로그아웃은 확인 창을 거친다. 목표가 없으면 목표 묶음 자리에 "목표 정하기" 한 줄을 둔다.
- 목표 관리 화면: 시스템 시각 선택기, 바닥 고정 영역에 요일 원이 가려지는 결함 수정, 학습 분 줄이기 확인은 저장을 누를 때 뜨는 확인 창 본문으로 옮긴다(기획서 5.3의 긁는 확인 문구는 유지).

### 4.6 피드백과 상태
- 갭분석 4절 F1~F16을 따른다. 버튼 눌림(크기 0.97), 정답 체크와 오답 흔들림, 위에서 내려오는 토스트, 스켈레톤 로딩, 당겨서 새로고침(홈, 기록), 완료와 달성 카운트업.
- 로딩은 300ms가 넘을 때만 보이고 10초가 넘으면 오류 상태로 바꾼다는 MVP 7.4-2 규칙을 유지한다.

## 6. 품질 기준

### 6.1 기존 기준 유지
- MVP 메가프롬프트 7.3(실패 동작), 7.4(화면 상태, 빈 화면 금지), 7.5(버튼 규칙), 7.6(문구), 7.7(정적 검사, 플랫폼, 접근성)을 계속 지킨다. 3절에서 예외로 정한 것만 바뀐다.
- 학습 시간 규칙(기획서 11.2)을 깨지 않는다. 화면이 켜져 있고, AI가 응답 중이 아니고(글자 표시 포함), 딴짓 팝업이 없고, 안내 모달이 없고, 연결돼 있을 때만 줄어든다. 서버 판정은 바뀌지 않는다.
- 강제 화면은 계속 나가는 길이 없다. 대신 할 일이 분명히 보인다.

### 6.2 모션 검증
1. 결정적인 스크린샷은 Playwright 컨텍스트에 `reduced_motion='reduce'`를 두고 찍는다. 기존 스크립트도 이 설정으로 바꾼다.
2. 움직임 자체는 따로 확인한다. 줄인 움직임을 끈 컨텍스트로 `record_video`를 켜고 주요 흐름(화면 전환, 시트, 단계 전환, 글자 표시, 정답과 오답, 카운트업, 포기 길게 누르기, 독촉 진입)을 녹화한다. `docs/모션/`에 짧은 webm으로 저장하고 전체 크기를 20MB 아래로 둔다.
3. 프레임 확인: 녹화에서 각 움직임이 시작과 끝 상태를 갖는지, 깜빡임이나 튐이 없는지 프레임을 몇 장 뽑아 직접 본다.
4. 줄인 움직임 켬과 끔 두 상태에서 같은 흐름이 끝까지 동작한다.
5. 웹은 네이티브 화면 전환과 스와이프 뒤로를 보여 주지 않는다. 실기기 확인 목록을 HANDOFF 5절에 남긴다.

### 6.3 성능
- 애니메이션은 UI 스레드에서 돈다(Reanimated worklet). JS 타이머로 프레임을 돌리지 않는다.
- 학습 화면은 1초 시계와 5초 저장이 돈다. 새 애니메이션이 이 갱신 때문에 다시 시작되거나 요청을 다시 보내지 않아야 한다. 주기적으로 다시 그려지는 컴포넌트에서 인라인 콜백을 effect 의존성에 넣지 않는다(9.3의 회귀 사례).
- 채팅 목록이 길어져도(메시지 200개) 스크롤이 끊기지 않는지 웹에서 확인한다.

### 6.4 UI/UX 관례 점검표
화면마다 아래를 확인하고 `docs/화면상태.md`에 새 표로 남긴다.
- 위쪽에 현재 위치(제목)와 나가는 길(chevron 또는 X)이 있다. 강제 화면은 예외이고 이유 한 줄이 있다.
- 주 버튼은 하나이고 엄지 자리에 있다. 키보드가 가리지 않는다.
- 누를 수 있는 것은 눌림 반응이 있다. 결과는 화면 변화, 토스트, 햅틱 중 하나로 알린다.
- 처음 보는 규칙은 처음 마주칠 때 한 번 설명된다.
- 로딩, 빈 데이터, 오류, 오프라인 상태가 모두 있다.
- 줄인 움직임과 큰 글자 150%에서 깨지지 않는다.

## 9. 지난 세션에서 얻은 사실과 교훈

### 9.1 SDK 57 사실 (확인됨)
- 버전 없는 Expo 문서는 SDK 58 기준이다. v57에는 `Stack.Protected`의 `redirectTo`가 없다. `usePreventRemove`는 `expo-router/react-navigation`에서 가져온다. 네이티브 탭 경로는 `expo-router/unstable-native-tabs`다.
- 탭은 `expo-router/js-tabs`를 쓴다(`expo-router`의 `Tabs`는 v57.0.28에서 폐기 예정).
- `getLastNotificationResponse()`는 v57에서 동기다. Android 알림 채널은 권한 요청 전에 만든다.
- Reanimated 4.5.1과 worklets 0.10.1 짝이 맞고 추가 babel 설정이 필요 없다. 웹에서 entering/exiting은 되지만 springify는 안 된다. 줄인 움직임 기본값은 웹에서 `matchMedia`를 읽는다.
- Stack의 `animation`, `presentation` 옵션은 iOS와 Android에서만 동작한다. keyboard-controller는 웹에서 아무것도 하지 않는다.
- 정확한 알람 권한을 읽는 Expo API는 없다. `modules/exact-alarm` 로컬 모듈이 있다.
- Windows에서는 `eas build --local`이 안 된다. EAS 클라우드 빌드만 쓴다.

### 9.2 로컬 환경
- Docker Desktop을 켜고 `npx supabase start`. 로컬 포트는 546xx다(API 54621, DB 54622, Studio 54623, Mailpit 54624). 다른 프로젝트가 543xx를 쓴다.
- AI 함수는 `AI_FAKE=1` 한 줄 env 파일로 `npx supabase functions serve --env-file <파일>`을 백그라운드로 띄워야 한다. 안 띄우면 "GEMINI_API_KEY missing"으로 실패한다. 다른 에이전트가 이미 띄웠으면 다시 쓴다.
- 앱은 `.env.local`(git 무시됨)에서 로컬 주소를 읽는다. 웹은 `npx expo start --web --port <포트>`. 코드 변경이 안 보이면 `--clear`로 다시 띄운다. `CI=1`이면 파일 감시가 꺼진다.
- 비밀번호 로그인은 심사용 이메일(`review@graego.app` / `local-review-only`)만 된다. 다른 테스트 사용자는 Mailpit의 OTP나 관리자 `generate_link`로 세션을 만든다. `scripts/e2e/lib.py`, `ui-lib.py`에 도우미가 있다.
- DB를 `db reset`하지 않는다. 마이그레이션은 `npx supabase migration up --local`로 올린다. 여러 에이전트가 같은 DB를 쓰므로 테스트 사용자 이름에 에이전트별 접두사를 붙인다.
- 이 셸에서 여러 줄 `python -c`는 실패한다. 스크립트 파일을 만들어 실행한다. 한글 출력은 `PYTHONUTF8=1`.
- 작업 사본은 CRLF로 바뀐다. 줄바꿈에 기대는 스크립트는 정규식으로 만든다(`scripts/sync-legal.ts` 참고).

### 9.3 교훈
- 수정 묶음 하나가 학습 화면에 회귀를 넣었다. `useNow(5000)`로 5초마다 다시 그려지는 화면이 인라인 `onGone={() => ...}`를 넘겼다. 그 콜백이 요청 함수의 의존성이라 5초마다 문항을 다시 불러왔고, 입력이 지워지고 딴짓 팝업이 무력화됐다. 독립 검증 에이전트가 잡았다. 애니메이션과 글자 표시를 넣을 때 같은 실수가 쉽다. 콜백은 `useCallback`으로 고정하고, 학습 화면을 바꾼 뒤에는 "10초 동안 입력 유지, 30초 동안 요청 반복 0회, 2분 딴짓 팝업"을 꼭 확인한다.
- 공용 파일(`copy.ts`, `store.ts`, `api.ts`)을 여러 에이전트가 동시에 고쳤을 때 중간 상태로 게이트가 잠깐 깨졌다. 소유 영역을 나누고, 오케스트레이터가 묶음이 끝난 뒤 게이트를 돌린다.
- 화면 확인은 웹 빌드로만 했다. 웹은 네이티브 전환, 스와이프, 햅틱을 보여 주지 않는다. 이번 작업의 핵심이 이 부분이므로 실기기 확인 목록을 빠짐없이 남긴다.
- 스크린샷 이름과 내용이 어긋난 적이 있다(같은 사진 두 장). 증거 파일은 해시가 겹치지 않는지 확인한다.
