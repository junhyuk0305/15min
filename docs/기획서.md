# 그래고 기획서 v3 (2026-10-07)

`[확인]` 표시는 사용자 결정이 필요한 항목이다. 결정되면 이 문서에서 표시를 지운다.

## 1. 정의

이름은 **그래고**. "그래, 고" 하고 시작하는 말이다.
목표를 정하면 달성할 때까지 매일 하게 만드는 앱이다. 안 하면 끈질기게 연락한다.
초기 분야는 영어 학습이다. 이후 코딩, 글쓰기로 넓힌다.

## 2. 원칙

1. 목표를 정했으면 달성할 때까지 한다. 어떤 일이 있어도 한다.
2. 매일 반복한다. `[확인 Q-B]`
3. 앱은 강제로 돕는다. 사용자의 편의보다 이행이 먼저다.
4. 목표를 정할 때와 매일 시작할 때마다 "나의 이유"를 쓴다.
5. 성공은 사용자가 끝까지 해내는 것이다. 알림은 그 수단이다. `[확인 Q-F]`

## 3. 사용자와 감정 경로

대상은 시작은 했지만 바쁘다는 이유로 멈춘 적이 있는 사람이다. 강제성을 보고 스스로 설치한다.

| 시기 | 사용자 감정 | 앱의 대응 |
|---|---|---|
| 첫날 | 결의 | 목표와 이유를 정하게 한다 |
| 1~2주 | 귀찮음, 다른 할 일 | 알림 문구 순환, 누적 분 노출 |
| 3주 이후 | "이걸 왜 하지" | 나의 이유를 본인 글로 다시 보여준다 |
| 지각한 날 | 회피 | 이유와 남은 분을 보여주고 시작 버튼 하나만 둔다 |

## 4. 핵심 정책

- **목표:** 이름, 달성 기준, 나의 이유를 정한다. `[확인 Q-A]`
- **학습 시간:** 하루 5~30분, 1분 단위.
- **반복:** 기존안은 주 5일 이상 필수. 원칙 2와 충돌한다. `[확인 Q-B]`
- **예외:** 아픔, 출장, 시험 같은 날의 처리. `[확인 Q-C]`
- **목표 변경·포기:** 허용 여부와 조건. `[확인 Q-D]`

## 5. 나의 이유

입력 시점은 두 번이다.
- **목표 설정:** 필수 입력. 비어 있으면 목표를 만들 수 없다.
- **매일 세션 시작:** 필수 입력. 쓰기 전에는 채팅이 열리지 않는다. 쓰는 시간은 목표 시간에서 차감하지 않는다. `[확인 Q-E]`

표시 위치
- 지각 상태의 홈 화면
- 독촉 알림 일부 (남은 분, 누적 분과 번갈아 사용)
- 아카이브의 일일 카드

## 6. 알림 설계

서버 푸시가 아니라 기기 로컬 알림으로 처리한다. 독촉 여부는 "이 기기에서 목표 시간을 채웠나"로만 정해진다.

예시: 22:00 시작, 목표 15분.

| 시각 | 동작 |
|---|---|
| 21:30 | 사전 알림 1회 |
| 22:00~22:15 | 유예. 알림 없음 |
| 22:15~23:14 | 미완료면 1분마다 60회 |
| 완료 | 예약된 알림 전부 취소 |

- 앱을 열 때마다 오늘 사이클 61개만 예약한다. iOS는 대기 로컬 알림이 64개까지다.
- 학습 중 백그라운드로 나가고 남은 시간이 있으면, 그 시각부터 60회를 다시 예약한다.
- 독촉 문구는 순환한다. 남은 분, 누적 분, 나의 이유를 섞는다.
- Android는 전용 채널을 만든다. iOS는 무음 모드를 뚫지 못한다.
- 사용자가 OS에서 알림을 끄면 막을 수 없다. 온보딩에서 권한을 받고, 홈에서 꺼짐을 감지해 알린다.

## 7. 학습 세션 규칙

- 화면이 켜져 있고 AI가 응답 생성 중이 아닐 때만 시간이 줄어든다. `[확인 Q3]`
- 2분 무입력이면 확인 팝업과 진동. 팝업 중에는 차감하지 않는다. `[확인 Q3]`
- 전송은 100자 이상일 때만 가능하다. `[확인 Q4]`
- 이탈 후 복귀하면 같은 채팅을 이어간다. 자정이 지나면 새 세션이다.
- 독촉 60회가 끝난 뒤의 처리. `[확인 Q5]`

## 8. 화면 목록

| 라우트 | 화면 | 핵심 요소 |
|---|---|---|
| /onboarding | 온보딩 | 가치 안내, 목표와 이유 입력, 시간 설정, 알림 권한 |
| / | 홈 | 누적 분, 마일스톤 게이지, 카운트다운, 봇 선택 |
| /reason | 오늘의 이유 | 한 줄 입력, 어제 이유 표시 |
| /session | 학습 채팅 | 남은 시간, 글자 수 게이지, 전송 |
| /bots, /bots/new | 봇 목록·생성 | 이름, 프롬프트 |
| /archive, /archive/[date] | 일일 카드 | 날짜, 소요, 봇, 글자 수, 이유 |
| /settings | 설정 | 시간, 요일, 알림 권한 상태 |

## 9. 데이터 모델 (기기 저장 기준)

- `goal`: name, startDate, 달성 기준, reason
- `settings`: startTime, targetMinutes, weekdays
- `bots[]`: id, name, systemPrompt, isBuiltin
- `sessions[]`: date, botId, reason, activeSeconds, completed, messages[], userCharCount
- `stats`: totalMinutes (sessions에서 파생)

## 10. 범위 밖 (1차)

로그인, 결제, 웹 배포, 영문판 진입 전략, 영어 외 분야. 영문판은 문자열을 한 곳에 모으는 구조만 처음부터 잡는다.

## 11. 미결 질문

기존
- Q1 계정과 백엔드. 로그인을 1차에 넣을지.
- Q2 AI 모델과 비용. 무료인지 구독인지.
- Q3 시간 차감과 딴짓 팝업 중 정지 규칙.
- Q4 최소 글자 수가 봇 공통인지.
- Q5 독촉 종료 후 그날 처리.

신규
- Q-A 목표의 끝. 기간, 누적 분, 본인 선언 중 무엇으로 "달성"을 정하는지. 달성하면 다음에 무엇이 일어나는지.
- Q-B 매일 vs 주 5일. 쉬는 날이 있는지.
- Q-C 예외. 아픈 날이나 출장 날을 허용하는지.
- Q-D 목표 변경·포기. 쉬우면 컨셉이 무너지고 막으면 삭제로 끝난다.
- Q-E 매일 이유가 복붙으로 굳는 문제. 최소 글자와 어제 이유 불러오기 허용 여부.
- Q-F 성공 지표. 완료율, 연속 일수, 30일 유지율 중 무엇을 볼지.
