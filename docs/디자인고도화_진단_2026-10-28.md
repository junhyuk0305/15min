# 디자인 고도화 진단 (2026-10-28)

## 0. 전제와 바로잡은 것

- 판정은 지금 코드 기준이다. `docs/화면상태/`의 auth, onboarding, goal-new 캡처는 10-19에 찍혀 현재 문구와 다르다.
- 메가프롬프트 2절의 "0분과 21시간 59분이 같은 크기"는 사실과 다르다. 0분은 48px(T.hero), 남은 시간은 34px(T.big)였다. 새 사용자에게 의미 없는 숫자가 더 컸다.
- 목표 정하기 2/3의 "시작 시각과 분이 같은 상자" 지적은 웹에만 맞다. 네이티브는 "22:00 ›" 버튼 하나다(TimePicker.tsx).

## 2. B. 레퍼런스와 화면별 최우선

앱스토어 lookup API로 9개 앱 69장을 내려받아 봤다. 듀오링고, 스픽, 케이크, 토스, 애플 피트니스, Streaks, Forest, HabitKit, 챌린저스.

| 볼 것 | 본 것 |
|---|---|
| 상태에 따라 무엇을 키우나 | 스픽 홈은 다음 수업 하나와 시작하기 하나다. 연속 일수는 오른쪽 위 작은 칩이다. 큰 숫자(100 연속일)는 수업을 끝낸 순간에만 키운다. 케이크 목표 화면은 "오늘 9분 50초 학습 중"을 상태 문장으로 둔다 |
| 처음 보는 요소 설명 | 스픽은 "불꽃" 라벨 옆 ⓘ와 한 줄 "불꽃 유지를 위해 내일도 꼭 수업을 완료해 주세요". 케이크는 "14일 연속 불꽃 켜기 3/14" 막대가 목표를 말한다. 달력에 연속을 지켜 준 날을 방패로 따로 표시한다 |
| 누르는 것, 입력, 정보 | 듀오링고 주 버튼은 폭 전체 채움, 선택지는 테두리 카드, 정보는 바탕 위 글자. Streaks 설정은 "라벨 : 값 ›" 행. Forest 시각은 채운 값 칩, 요일은 원형 토글 |
| 큰 숫자 하나를 고르는 기준 | 지금 행동을 바꾸는 숫자 하나. 토스 계좌 목록은 같은 크기, 증권 상세만 총액 하나를 키운다. 애플 피트니스는 목표 대비 "665/750" |

## 3. C. 규칙 누락 점검

| 규칙(출처) | 어긋나던 화면 | 처리 |
|---|---|---|
| 같은 무게 금지(mobile-app-ui-design Anti-Patterns) | 홈 전 상태 | 누적을 한 줄로 내림 |
| 빈 상태에 안내(ui-ux-pro-max Empty States) | 홈 첫 학습 전 이번 주 띠 | 한 줄 추가 |
| 사용자 단계별 안내(Personalization by User Stage) | 홈 첫 학습 전 | 순서 미리보기, 0 숫자 숨김 |
| 입력은 입력처럼 보이게(Input Affordance) | 목표 2/3 | C안 반영(값 한 줄과 칩, 요약을 다른 모양으로) |

기존 체계와 부딪쳐 따르지 않는 권고:
- 글자 크기 4종 이하. 테마가 7종(hero, big, h1, h2, body, small, label)을 정본으로 쓴다.
- 튜토리얼은 건너뛸 수 있게. 첫 학습 규칙 모달은 건너뛰기가 없는 것이 결정된 설계다(갭분석 3.1-4).
- 완료 축하 강조(Peak-End). 격려를 아끼는 기획서 원칙과 부딪친다.

## 4. 처리 결과

막힘 1~13, 16을 제외한 반영 상태는 `docs/결정로그.md` 4절에 있다. 남은 것은 아래다.
- 14 포기 진입이 목표 관리 안에 있음: 그대로 둔다. 의도된 마찰일 수 있다.
- 15 기록 달력 빈 칸 범례, 상세 숫자 라벨: 이번 범위 밖.
- 16 회고 3분을 채웠는데 홈에 "1분 남음": 이번 범위 밖. index.tsx `Math.max(1, left)`.

## 5. 안 본 것

- 실기기(키보드, 알림 탭 진입). 웹 캡처와 코드로만 봤다.
- 학습과 회고 화면은 다시 찍지 않았다. 로컬 함수 서버(edge runtime 컨테이너)가 뜨지 않았다. 표현 보기와 회고 뜻은 단위 테스트와 함수 테스트로만 확인했다.
