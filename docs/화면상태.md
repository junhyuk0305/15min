| 상황 | 동작 | 스크린샷 |
|---|---|---|
| 앱 시작 | 세션 확인과 첫 읽기가 끝날 때까지 스플래시. 10초가 넘으면 캐시로 연다(`_layout` BOOT_TIMEOUT_MS). 웹은 그동안 가운데에 진행 표시와 "불러오는 중입니다."를 보인다. 캐시가 있어도 첫 읽기가 끝나거나 10초가 지나야 화면이 뜬다 | home-loading, home-loading-cache |
| 첫 읽기 실패, 캐시 없음 | 오류 화면 "앱을 열지 못했습니다" + 두 문장 안내. 주 버튼 "다시 불러오기" | home-error-cold, home-loading-10s |
| 캐시 있음, 읽기 실패 | 캐시를 그대로 보이고 화면 위에 빨강 배너(`StatusBanner`). 네트워크면 "연결이 끊겨 마지막으로 받은 내용을 보여 줍니다.", 그 밖은 "최신 내용을 불러오지 못했습니다. 다시 불러오기를 누르십시오." 배너 안 글자 버튼 "다시 불러오기" | home-error, home-offline |
| 렌더 오류 | 오류 화면 "화면을 그리지 못했습니다" + "오류를 기록했습니다. 다시 열기를 눌러 주십시오." 주 버튼 "다시 열기". 누르면 홈으로 돌아온다. 개발 빌드 웹에서 `/?crash=1`로 띄웠다 | crash-error, crash-recovered |
| 서버 주소 없음 | 오류 화면 "앱 설정이 없습니다". 버튼 없음(개발 빌드 전용 상황) | 찍지 않음(`.env.local`이 있어야 웹이 뜸) |

- 가로 넘침은 0장이다. 화면 밖으로 나간 글자도 없다. 목표 설정 위쪽 요약 칩의 이유 글은 말줄임으로 잘리는데 의도한 모양이다.

### 큰 글자

웹에는 시스템 글자 크기가 없어 화면의 모든 글자를 1.5배로 키워 대신 봤다(`scripts/e2e/ui-checks.py`). 위치는 `docs/화면상태/large-text/<화면>-150.png`.
홈 독촉, 홈 대기, 학습 A, B, C, 오늘의 이유, 목표 설정, 설정, 목표 관리, 포기 확인, 기록, 로그인 12개 화면에서 주 버튼 글자가 버튼 밖으로 나가거나 잘린 곳은 없다. 가로 넘침도 없다.
실기기 최대 글자 크기(iOS 접근성 큰 글자 310%)는 웹으로 재현할 수 없어 확인하지 못했다.

### 대비

같은 12개 화면에서 글자색과 실제 바탕색(겹친 반투명까지 계산)으로 WCAG 대비를 쟀다.
켜진 글자는 모두 4.5:1 이상이다. 가장 낮은 값은 아이보리 바탕 위 빨강 글자 4.98(계정 삭제, 포기 신청, 글자 수 0/20)과 보조 회색 글자 5.03이다.
4.5 미만은 비활성 버튼 글자뿐이다(1.85~3.44). 비활성 버튼은 WCAG 대비 대상이 아니다.
입력칸 안내 글(placeholder)은 `C.disabled` 색이라 약 1.9:1이었다(결함 13). 수정 뒤 모든 입력칸이 보조 회색(`C.sub`, `p.sub`)을 쓴다. 같은 색 글자를 위에서 5.03으로 쟀다. 재촬영 뒤 대비 스크립트(`ui-checks.py`)는 다시 돌리지 않았다.

### 아이콘 버튼 접근성 이름

글자 없이 기호만 있는 버튼은 모두 접근성 이름이 있다. 신고 "!" → "이 응답 신고하기", 달력 "‹ ›" → "이전 달 보기", "다음 달 보기", 스테퍼 "− +" → "시작 시각 줄이기" 등, 분 칩 ":15" → "시작 분 15".
Playwright 접근성 스냅샷은 `ui-checks.py`가 화면마다 남긴다(UI_META 폴더의 `aria-<화면>.yml`).

### 달력 상태

색 없이도 구분된다. 칸마다 기호를 같이 쓴다: 완료 ○(검정 채움), 실패 ×(빨강 채움), 쿠폰 □(굵은 테두리), 쉬는 요일 –, 포기 대기 !. 범례도 같은 기호다.
완료 칸은 버튼이고 "10월 17일 완료"처럼 이름이 있다. 누를 수 없는 칸은 웹 접근성 트리에 "13 ×"처럼 숫자와 기호로만 나온다. 네이티브는 `accessibilityLabel`이 있어 이름으로 읽을 것으로 본다. 실기기 확인은 못 했다.

## UX 고도화: 화면별 관례 점검(6.4)

2026-10-19 U9-A. 근거는 이번 재촬영 사진(`docs/화면상태/*.png`, `large-text/*-150.png`)과 스크립트 결과(`ui-states.py`, `ui-checks.py`, `ui-report.py`, `scenarios.py`)다. 판정은 통과, 예외(사유), 미검증(사유)로 적는다. `3b892f2`(U9 수정 묶음)로 바뀐 칸은 HEAD `ff6b1cd` 부분 재촬영 사진으로 다시 판정했고 칸 안에 결정로그 번호(D1~D11, M3, M5)를 적었다. 판정이 바뀐 칸은 없다.

모든 화면에 같은 판정 세 가지는 표에서 줄여 적었다.
- 눌림 반응: 사진에는 눌린 순간이 찍히지 않는다. 그래서 칸에는 결과 알림(화면 변화, 토스트, 시트)만 판정하고 눌림 모양은 미검증이다. 코드로는 Button, Card, Row가 0.97 + 불투명도 0.9다(결정로그 3.2 "눌림"). 햅틱은 웹에 없어 미검증이다(HANDOFF 5절 실기기).
- 키보드: 웹은 키보드를 띄우지 않는다. 입력이 있는 화면은 "키보드 미검증(웹)"이다.
- 줄인 움직임: 모든 사진을 `reduced_motion='reduce'`로 찍었고 깨진 화면은 없었다. 칸에는 큰 글자 150%만 따로 적는다. 150%는 `ui-checks.py`의 12화면만 찍는다. 나머지는 미검증(스크립트 범위 밖)이다.
