목적: 사용자와 합의한 학습 방향과 남은 질문 정리.
상태: 논의 중. 구현 전. 0절은 현재 방향. 1~13절은 최초 3안 비교 자료.
기준: `기획서.md` v8의 2절, 10절, 11절. `기획안_발표용.md` 4절.

`[가정]`은 검증 전 제안이다. `[확인]`은 사용자 결정이 필요한 항목이다.
아래 시간 배분과 학습량은 모두 `[가정]`이다. 효과가 입증된 수치가 아니다.

## 0. 대화에서 정한 현재 방향

이 절이 이전 3안 비교보다 우선한다. 이전 안의 원문 재작성 흐름은 아래의 새 질문 적용 흐름으로 바꾼다. 이후 절에 남은 목표 선택 질문은 이번 논의로 대체한다.

### 0.1 학습 목표

**특정 상황에서 필요한 단어와 표현을 떠올려, 영어로 답하고 대화를 이어간다.**

서비스 문구: **하고 싶은 말이 영어로 바로 떠오르도록.**

단어와 표현을 함께 배운다. 짧은 응답에서 시작한다. 필요한 지식을 배운 뒤 경험과 의견을 설명하는 답변으로 넓힌다.

### 0.2 최초 목표 설정

맨 처음 목표를 설정할 때 상황과 사용자 역할을 찾는다. 매일 목표 설정을 반복하지 않는다.

예: 스타벅스에서 음료를 주문하는 고객. 고객 입장에서 받을 질문과 해야 할 말을 수업으로 구성한다.

`[가정]` 상황은 장소, 사용자 역할, 상대 역할, 대화 목적까지 정리한다. 목표 이름과 함께 저장한다. 상황의 변경 방법은 아직 정하지 않는다.

| 항목 | 예시 |
|---|---|
| 장소 | 스타벅스 매장 |
| 사용자 역할 | 음료 주문 고객 |
| 상대 역할 | 주문 담당 직원 |
| 대화 목적 | 주문과 옵션 선택 |
| 후속 장면 | 품절 대안, 주문 변경, 주문 오류 문의 |

서비스가 사용자의 목표 상황에서 답할 수 있도록 수업을 만든다. 상황과 인물이 바뀌어도 A, B, C의 학습 흐름은 유지한다.

### 0.3 하루 흐름

| 단계 | 내용 | 15분 배분 초안 |
|---|---|---|
| A | 이전 단어와 표현 복습 | 3분 |
| B | 상황 대화, 코치 설명, 새 질문 적용 | 9분 |
| C | 오늘 단어와 표현 복습 | 3분 |

A와 C에는 퀴즈와 플래시카드를 섞는다. 정해진 문항 수를 모두 맞혀야 시간이 끝나는 방식은 정하지 않았다. 3분 회고는 현재 정본대로 별도다.

### 0.4 B단계

상황 질문 → 사용자 답변 → 코치 모달 → 비슷한 새 질문 → 새 표현 적용 → 다음 질문으로 진행한다.

모달에는 설명 문장과 영어 항목의 한국어 뜻을 넣는다. 사용자가 설명을 보고 어떻게 표현할지 스스로 이해한다. 방금 질문에 대한 완성 답변을 복사하는 흐름은 피한다.

예:

> 직원: Would you like regular milk?
>
> 사용자: No. Oat milk please.

코치 모달:
- 표현: Could I have … instead?
- 뜻: 대신 …로 받을 수 있을까요?
- 설명: 제안한 것을 다른 것으로 바꿔 달라고 요청할 때 씁니다.
- 단어: instead. 대신, 그 대신.

새 질문:

> 직원: We only have hot coffee ready. Would that be okay?
>
> 사용자: Could I have iced coffee instead?

뜻이 전달된 첫 답을 오답으로 처리하지 않는다. 다른 표현을 배우는 기회로 삼는다. 새 질문은 같은 기능을 연습하도록 구성한다. 동시에 배울 필요가 없는 어려운 단어를 추가하지 않는다.

`[가정]` 모달에서 배운 뒤 새 질문에 답한 것은 도움 후 적용으로 기록한다. 모달을 닫았다는 이유만으로 독립 수행이 되지는 않는다.

### 0.5 A와 C의 난이도 제안

`[가정]` C는 당일 학습 확인, A는 시간이 지난 뒤의 유지 확인으로 둔다. A가 항상 더 어려운 문제를 주지는 않는다. 첫 시도의 수준을 비슷하게 맞춰 기억 유지 여부를 본다.

| 문제 유형 | 예시 | 확인 대상 |
|---|---|---|
| 뜻 선택 | instead의 문맥상 뜻 선택 | 뜻 인식 |
| 직접 회상 | 대신 → 영어 단어 입력 | 단어 회상 |
| 표현 회상 | 다른 옵션을 요청하는 표현 작성 | 표현 회상 |
| 새 질문 응답 | 직원의 새로운 제안에 변경 요청 | 상황 적용 |

C는 짧은 뜻 확인 뒤 직접 회상과 상황 적용으로 이어간다. 당일 성과만 기록한다. A는 도움 없는 회상을 먼저 시도한다. 막히면 힌트나 선택지를 준다. 도움 전 첫 답과 도움 후 답을 따로 저장한다.

플래시카드를 스스로 뒤집고 기억했다고 체크한 결과는 자기 보고다. 직접 입력하거나 선택한 답과 구분한다. 정답을 보여 준 뒤 같은 답을 쓴 경우에는 독립 회상으로 세지 않는다.

복습 대상은 어제 항목, 이전에 막힌 항목, 복습 시점이 된 오래된 항목에서 고른다. 첫날에는 A를 짧은 수준 확인으로 대체한다. 문항 수와 비중은 `[확인]`이다.

연구 참고: Smith와 Karpicke의 2014년 실험에서는 객관식, 단답형, 혼합형 복습이 모두 단순 재학습보다 유지에 도움이 됐다. 어려운 단답형이 항상 가장 좋지는 않았다. 이 결과는 그래고의 영어 회화 수업을 직접 검증한 결과가 아니다. 문제 난도만 높이기보다 회상 성공과 피드백을 함께 고려하는 근거로 쓴다. [논문 원문](https://learninglab.psych.purdue.edu/downloads/2014/2014_Smith_Karpicke_Memory.pdf)

### 0.6 새 지식과 기록

AI와 사용자가 쓴 단어와 표현을 저장한다. 새 학습 항목의 중복을 확인할 근거로 쓴다.

`[가정]` 등장한 모든 항목을 이미 익힌 것으로 취급하지 않는다. 처음 등장, 코치 설명, 사용자 사용, 복습 성공을 구분한다.

| 기록 | 의미 |
|---|---|
| AI 메시지 등장 | 본 적 있는 항목 |
| 코치 설명 | 명시적으로 배운 항목 |
| 사용자 사용 | 직접 작성한 항목 |
| 도움 없는 이후 회상 | 시간이 지난 뒤의 기억 확인 |

새 학습 후보는 목표 상황에 필요한 항목 중 아직 명시적으로 가르치지 않은 것부터 고른다. 등장했지만 사용하지 못한 항목도 설명 대상이다. 배웠지만 기억하지 못하는 항목은 재학습 대상이다. 이미 아는 항목은 새 학습 수에 넣지 않는다.

새 학습 수는 단어와 표현을 따로 센다. drink와 drinks처럼 형태만 다른 단어, Could I have tea?와 Could I have coffee?처럼 내용만 다른 같은 표현 패턴은 중복 집계를 피한다. 같은 단어의 다른 뜻과 용법은 구분한다.

`[확인]` 기록에 없는 항목만 학습할지, 등장했지만 못 쓰는 항목도 가르칠지. 추천은 후자다. 기존 표현은 B에서도 새 표현과 함께 쓴다. 모든 대화 문장을 새로운 단어만으로 만들지는 않는다.

### 0.7 다음 질문

- `[확인]` A와 C의 문제 비중. 추천은 단어의 짧은 퀴즈와 표현의 직접 답변 혼합.
- `[확인]` 복습할 때 코치 모달 열기. 추천은 먼저 도움 없이 시도한 뒤 열기 허용.
- `[확인]` 하루 새 단어 수와 표현 수. 실제 세션을 만들어 분량 확인 필요.

## 1. 추천

첫 학습 목표는 **익숙한 상황에서 필요한 말을 영어로 직접 써서 주고받기**를 추천한다.

대상은 단어를 처음 접하는 사람이 아니다. 알아보는 영어를 직접 쓰는 영어로 바꾸는 데 초점을 둔다. 채팅에서는 짧게 답하고 상대의 반응에 맞춰 다시 표현할 수 있다. 처음 쓴 문장과 고친 문장도 남는다.

대표 콘텐츠는 1안인 상황 해결 채팅을 추천한다. 2안은 자기 이야기를 하고 싶은 사람에게 맞는다. 3안은 영어 문장을 시작하기 어려운 사람에게 맞는다. 처음부터 셋을 모두 기본 봇으로 제공할지는 정하지 않는다.

텍스트 채팅으로 확인할 성과는 영어 문장 작성과 문자 대화다. 발음, 듣기, 실제 발화 속도는 별도 측정이 필요하다. 이 기획만으로 회화 실력 향상을 보장하지 않는다.

## 2. 학습 목표를 정하는 방법

목표는 **사용할 상황 + 할 행동 + 도움의 정도 + 확인할 과제**로 정한다.

예: 약속 시간을 바꿔야 할 때, 예문 없이 이유와 대안을 적고, 상대와 새 시간을 합의하기.

| 구분 | 예시 | 확인 방법 |
|---|---|---|
| 습관 목표 | 주 5일, 하루 15분 학습 | 학습 시간과 완료 기록 |
| 학습 목표 | 영어로 일정 변경 요청 | 조건을 바꾼 새 채팅 과제 |
| 하루 목표 | 변경 이유와 대안 전달 | 상대에게 필요한 정보의 포함 여부 |
| 유지 여부 | 며칠 뒤 같은 기능의 재사용 | 예문 없는 다른 상황에서의 답변 |

기간 달성은 기존 기획대로 본인이 선언한다. 학습 성과는 별도 기록으로 보여준다. 학습 평가가 낮아도 정해진 학습과 회고를 마치면 하루 완료다. 평가를 새 페널티 조건으로 추가하지 않는다.

### 2.1 회화와 단어 암기의 위치

| 후보 목표 | 채팅에서 가능한 활동 | 그래고의 초기 우선순위 |
|---|---|---|
| 문자 대화 | 질문, 답변, 재질문, 합의 | 높음 |
| 짧은 작문 | 메시지 작성, 문장 수정 | 높음 |
| 어휘 사용 | 뜻 회상, 상황에 맞는 표현 작성 | 보조 학습 |
| 읽기 | 상대 메시지 이해, 정보 확인 | 대화 안에 포함 |
| 듣기와 발음 | 음성 청취, 녹음, 발화 평가 | 텍스트 기획 범위 밖 |

`[가정]` 단어 뜻 맞히기를 대표 콘텐츠로 삼지 않는다. 대상자가 과거에 중단한 방식과 비슷하다. 어휘는 그날 써야 할 표현을 꺼내 쓰는 활동에 포함한다.

## 3. 다른 서비스에서 참고할 것

공식 설명에서 학습 방식을 확인했다. 아래 비교는 그래고에도 같은 효과가 난다는 근거가 아니다. 요금제와 제공 언어는 비교 대상에서 제외했다.

| 서비스 | 공식 설명의 학습 방향 | 대표 활동 | 그래고에 적용할 요소 |
|---|---|---|---|
| 스픽 | 실제 대화에 쓰는 말하기 | 표현 학습, 연습, AI 대화 적용 | 표현을 배운 뒤 다른 상황에 사용 |
| 듀오링고 | 수준별로 할 수 있는 행동 | 단계별 과정, 복습, 상황 역할극 | 하루 목표 지정, 수준에 맞는 상대 발화 |
| 링글 | 목적에 맞는 대화와 표현 개선 | 수업 준비, 튜터 대화, 교정, 복습 | 원문과 수정문 보관, 반복되는 약점 확인 |

스픽은 Learn, Practice, Apply 순서를 설명한다. 그래고에는 짧은 표현 연습 뒤 실제로 쓰게 하는 순서가 참고점이다. [스픽 공식 소개](https://www.speak.com/)

듀오링고는 CEFR의 수행 목표를 과정 설계에 쓴다. 역할극에도 상황과 학습자 수준을 지정한다. 그래고에도 오늘 해야 할 행동과 AI가 쓸 언어의 수준이 필요하다. CEFR 공식 등급 판정은 이 기획에 포함하지 않는다. [과정 설계](https://blog.duolingo.com/the-nuts-and-bolts-of-course-creation-at-duolingo/), [역할극 설계](https://blog.duolingo.com/chatbot-language-practice/)

링글은 대화 중 교정과 수업 후 피드백을 제공한다. 복습 자료에는 교정 표현과 수업 기록이 포함된다. 그래고에는 사용자가 실제로 쓴 문장에서 다음 과제를 정하는 방식이 참고점이다. [수업 방식](https://www.ringleplus.com/ko/student/landing/how-it-works), [수업 복습](https://www.ringleplus.com/ko/student/landing/blog/ringle-lesson-review-3.0)

기획 판단: 그래고에는 짧은 수행 목표, 직접 작성, 재사용 확인을 함께 두는 방식이 맞는다. 매일 무엇을 할지 사용자가 새로 고민하게 만들지 않는다.

## 4. 공통 세션 원칙

### 4.1 15분의 의미

15분은 앱 타이머가 센 학습 시간이다. AI가 답변을 만드는 시간은 제외한다. 메시지를 읽고 생각하는 시간은 현재 규칙상 포함된다. 실제 키보드 입력 시간만 세는 것은 아니다.

시작 전 이유 작성과 3분 회고는 별도다. 총 소요 시간은 **이유 작성 + 학습 15분 + 회고 3분 + AI 응답 대기**다. 실제로 하루 15분만 쓸 수 있는 사용자와는 차이가 있다.

`[확인]` 15분을 학습 시간으로 유지할지, 전체 이용 시간에 맞출지 결정해야 한다. 현재 비교안은 정본대로 학습 15분을 유지한다. 전체 15분이 필요하면 이유 작성과 응답 대기까지 실측한 뒤 학습 시간을 다시 정한다.

분 단위 배분은 진행 기준이다. 시간을 채우려고 같은 문장을 반복시키지 않는다. 빨리 끝나면 조건을 바꾼 재사용 과제를 준다. 느리면 새 표현과 추가 문제를 줄인다. 종료 시점에 풀지 못한 과제는 다음 날로 넘긴다.

### 4.2 입력 부담

100자 전송 제한은 낮추는 쪽을 추천한다. “Could we meet at six?”처럼 짧아도 필요한 일을 하는 문장이 있다. 길이 제한이 핵심 표현보다 군더더기를 늘릴 수 있다.

`[가정]` 기본 학습 봇의 최소 글자 수는 공백을 제외한 1자로 둔다. 글자 수는 빈 입력 방지에만 쓴다. 과제는 상황에 맞는 한 문장부터 시작한다. 불충분한 답에는 필요한 정보를 다시 묻는다. “이유도 한 문장으로 적어 주세요.”처럼 안내한다.

짧은 대답이 자연스러운 차례에는 짧게 답하게 한다. 뜻 없는 반복 입력은 학습 성과로 세지 않는다. 커스텀 봇의 최소 글자 수 설정은 유지한다.

`[확인]` 기본 봇의 최소 글자 수 변경. 현재 100자 규칙과 위 예시 대화는 함께 적용할 수 없다.

### 4.3 AI 말투

코치는 정중한 한국어 존댓말을 쓴다. 역할극 상대는 쉬운 영어를 쓴다. 말풍선 안에 역할을 구분한다.

- 한 번에 질문 하나.
- 교정은 현재 목표에 중요한 것 하나.
- 이해를 막는 오류는 즉시 확인.
- 작은 오류는 대화가 끝난 뒤 교정.
- 막히면 한국어 뜻, 문장 시작, 예문 순서로 도움 제공.
- 예문을 본 답변과 혼자 쓴 답변의 기록 분리.

학습 중에는 오류와 다음 행동을 알려준다. 예: “변경할 시간을 더해 주세요.” 학습 실수를 독촉 말투로 지적하지 않는다. 완료 시 격려는 정본의 완료 흐름을 따른다.

2분 무입력 팝업은 유지한다. 긴 기사와 장문 작문은 초기 과제에서 피한다. 읽기와 생각이 긴 과제일수록 이 규칙과 충돌한다.

## 5. 1안: 상황 해결 채팅

**영어 메시지로 필요한 일을 끝내는 연습이다. 대표 콘텐츠로 추천한다.**

약속 변경, 예약 확인, 잘못 온 주문 문의처럼 목적이 있는 대화를 한다. 상대가 답한 내용을 읽고 다음 문장을 직접 쓴다.

### 5.1 목표와 성과

목표 예시: “약속 시간을 바꿀 때 이유와 대안을 영어로 보내기.”

하루 과제는 시간 변경 요청이다. 상대에게 변경 의사가 전달됐는지 본다. 가능한 대안을 제시했는지도 본다. 예문 없이 다른 약속을 변경하면 독립 수행으로 기록한다.

`[가정]` 첫 4주에는 요청, 확인, 변경, 거절을 다룬다. 주당 하나의 기능을 여러 상황에서 쓴다. 4주 뒤에는 처음 보는 짧은 상황으로 다시 확인한다. 달성 보장 기간은 아니다.

### 5.2 15분 구성

| 시간 | 단계 | 사용자 활동 |
|---|---|---|
| 0~2분 | 시작 | 지난 표현 회상, 오늘 요청 첫 시도 |
| 2~5분 | 준비 | 필요한 표현 1~2개 연습 |
| 5~11분 | 본 학습 | 상대의 답변에 따른 요청과 조정 |
| 11~13분 | 교정 | 핵심 오류 한 곳 수정, 재작성 |
| 13~15분 | 마무리 | 다른 상황에서 힌트 없는 재사용 |

### 5.3 예시 대화

> 코치: 오늘은 약속 시간을 바꿉니다. 늦는 이유와 새 시간을 보내 주세요.
>
> 상대: Can we meet at five?
>
> 사용자: I work until six. Can we meet at seven?
>
> 상대: Seven is too late. How about tomorrow?
>
> 사용자: Tomorrow good. At six?
>
> 코치: “Tomorrow works for me.”로 답할 수 있습니다. 시간도 함께 적어 주세요.
>
> 사용자: Tomorrow works for me. Can we meet at six?
>
> 상대: Sure. See you tomorrow at six.

마지막 과제는 음식점 예약 변경으로 바꾼다. 방금 문장을 그대로 보여주지 않는다. 같은 뜻을 다른 표현으로 써도 인정한다.

### 5.4 채팅에 맞는 이유와 한계

요청을 보내면 상대가 반응한다. 사용자 답변에 따라 다음 조건이 달라진다. 채팅 자체가 연습하려는 행동이다.

단순한 역할극만 반복하면 배운 표현을 잊을 수 있다. 다음 날 첫 과제에서 다시 쓰게 한다. AI가 무조건 수락하면 성과를 판별하기 어렵다. 필수 정보가 빠지면 상대가 확인 질문을 해야 한다.

### 5.5 매일 바꾸는 것

`[가정]` 최근 7회 안에는 같은 상황, 상대, 장애물 조합을 쓰지 않는다. 표현은 복습을 위해 반복한다.

예: 친구와 약속 변경 → 음식점 예약 변경 → 배송일 변경. 배우는 기능은 변경 요청으로 유지한다. 상대의 반응은 가능한 시간 제안, 추가 정보 요청, 첫 제안 거절로 바꾼다. 초반에는 장애물을 하나만 둔다.

## 6. 2안: 내 일상 설명 채팅

**자기 경험과 생각을 짧은 영어로 설명하는 연습이다.**

AI가 사용자의 하루에서 사건 하나를 고른다. 무슨 일이 있었는지 듣고 이유나 느낌을 묻는다. 대화 끝에 사용자가 자기 이야기를 다시 정리한다.

### 6.1 목표와 성과

목표 예시: “오늘 있었던 일과 내 생각을 영어 3문장으로 설명하기.”

사건, 이유, 생각이 전달되는지 본다. 질문 없이도 내용을 연결하는지 본다. 다음 날 다른 사건을 같은 수준으로 설명하면 재사용으로 기록한다. 문장 수는 연습 분량이며 실력 점수가 아니다.

### 6.2 15분 구성

| 시간 | 단계 | 사용자 활동 |
|---|---|---|
| 0~2분 | 시작 | 사건 하나 선택, 영어 한 문장 작성 |
| 2~6분 | 본 학습 | AI 질문에 따른 사건 설명 |
| 6~10분 | 확장 | 이유, 느낌, 다음 행동 설명 |
| 10~13분 | 교정 | 필요한 표현 연습, 문장 재작성 |
| 13~15분 | 마무리 | 도움 없이 사건과 생각 정리 |

### 6.3 예시 대화

> 코치: 오늘 계획과 달라진 일을 한 문장으로 적어 주세요.
>
> 사용자: I missed bus this morning.
>
> AI: What did you do next?
>
> 사용자: I took taxi because I have meeting.
>
> 코치: 지난 일이므로 “had a meeting”을 씁니다. 그 문장을 다시 적어 주세요.
>
> 사용자: I took a taxi because I had a meeting.
>
> AI: What will you do differently tomorrow?
>
> 사용자: I will leave home ten minutes earlier.

마지막에는 사건과 이유를 스스로 다시 적는다. AI가 완성한 일기를 대신 제공하고 끝내지 않는다.

### 6.4 채팅에 맞는 이유와 한계

앞선 답변에서 다음 질문이 나온다. 긴 일기를 처음부터 써야 하는 부담이 적다. 남는 문장도 사용자의 실제 이야기다.

매일 특별한 일이 있어야 한다는 부담이 생길 수 있다. 이야기할 일이 없으면 작은 선택이나 가상 상황을 제시한다. “오늘 마신 음료”처럼 사소한 소재도 허용한다.

3분 회고와 겹칠 위험이 크다. 본 학습에서는 사건을 설명하는 능력을 다룬다. 회고에서는 막힌 표현과 다음에 연습할 것을 묻는다. 하루 이야기를 다시 요구하지 않는다.

### 6.5 매일 바꾸는 것

`[가정]` 질문 유형을 사건 설명, 선택 이유, 비교, 다음 계획으로 돌린다. 같은 첫 질문은 연속으로 쓰지 않는다. 전날 사용자가 말한 계획은 실행 여부를 묻는 재료로 쓴다. 말하지 않은 일을 AI가 만들어내지 않는다.

## 7. 3안: 아는 표현 꺼내 쓰기

**눈에 익은 단어와 표현을 필요한 순간에 직접 쓰는 연습이다.**

단어 뜻을 맞힌 뒤 끝내지 않는다. 뜻만 제시받고 영어 표현을 떠올린다. 이후 다른 상황의 짧은 채팅에서 사용한다.

### 7.1 목표와 성과

목표 예시: “일정 조율 표현을 예문 없이 꺼내 쓰기.”

`[가정]` 하루 새 표현은 2개로 시작한다. 이전 표현 2개를 함께 복습한다. 쉬우면 상황을 바꾼다. 새 표현 수를 먼저 늘리지 않는다.

뜻을 알아보는지, 직접 떠올리는지, 문맥에 맞게 쓰는지를 나눠 기록한다. 며칠 뒤 다른 상황에서 다시 쓰기 전에는 익힌 표현으로 확정하지 않는다.

### 7.2 15분 구성

| 시간 | 단계 | 사용자 활동 |
|---|---|---|
| 0~3분 | 시작 | 지난 표현 2개 회상 |
| 3~6분 | 학습 | 새 표현 2개의 뜻과 용법 확인 |
| 6~10분 | 본 학습 | 뜻을 보고 직접 작성, 상황 변경 |
| 10~13분 | 적용 | AI와 짧은 상황 대화 |
| 13~15분 | 마무리 | 예문 없는 표현 재사용 |

### 7.3 예시 대화

> 코치: “금요일은 시간이 됩니다”를 영어로 적어 주세요.
>
> 사용자: Friday is possible.
>
> 코치: 일정이 괜찮다는 뜻으로 “Friday works for me.”를 쓸 수 있습니다.
>
> 코치: 이번에는 화요일 오전이 괜찮다고 답해 주세요.
>
> 사용자: Tuesday morning works for me.
>
> 상대: Can we have lunch on Tuesday?
>
> 사용자: Tuesday doesn't work for me. How about Wednesday?

첫 답도 뜻은 통한다. 오답으로 단정하지 않는다. 새 표현을 쓴 여부와 의사 전달 성공을 따로 기록한다.

### 7.4 채팅에 맞는 이유와 한계

사용자가 틀린 부분에 따라 힌트를 바꿀 수 있다. 외운 표현을 대화에 옮기는 과정도 같은 화면에서 이어진다.

세 안 중 퀴즈 앱과 가장 비슷해질 위험이 크다. 객관식과 빈칸만 이어지면 채팅 UI의 이점이 줄어든다. 단독 대표 콘텐츠보다는 첫 문장을 못 쓰는 사람의 준비 과정으로 추천한다.

### 7.5 매일 바꾸는 것

`[가정]` 표현별 다음 복습 시점을 둔다. 첫 재확인은 다음 학습일에 한다. 성공하면 간격을 늘리고 막히면 다음 학습일에 다시 다룬다. 같은 문항은 피하고 인물과 시간을 바꾼다. 앱을 열지 않은 날을 기억력 실패로 기록하지 않는다.

## 8. 세 안의 선택 기준

아래 비교는 기획 판단이다. 사용자 실험 결과가 아니다.

| 항목 | 1안 상황 해결 | 2안 내 일상 설명 | 3안 표현 꺼내 쓰기 |
|---|---|---|---|
| 중심 성과 | 요청과 합의 | 경험과 생각의 설명 | 표현의 회상과 사용 |
| 채팅 활용 | 상대 반응에 따른 행동 변경 | 답변에 따른 후속 질문 | 오류에 따른 힌트 변경 |
| 첫날 부담 | 중간 | 중간 | 낮음 |
| 반복 동기 | 상황 해결 결과 | 내 이야기 기록 | 기억한 표현의 증가 |
| 주요 위험 | 비슷한 역할극 반복 | 회고와의 중복 | 기존 단어 공부와의 유사성 |
| 추천 용도 | 대표 콘텐츠 | 자기 표현 중심 선택지 | 초반 보조 훈련 |

`[확인]` 대표 목표 선택. 추천은 1안이다. “영어로 자기 이야기를 하고 싶다”가 핵심 수요라면 2안이 맞다. “아는 단어도 하나도 안 나온다”가 핵심 문제라면 3안부터 시작한다.

## 9. 첫날 진단과 난이도

`[가정]` 첫날 학습의 앞 5분을 짧은 수행 진단으로 쓴다. 기존 시작과 준비 시간을 대체한다. 별도 시험 시간을 더하지 않는다.

1. 익숙한 상황에서 한 문장을 직접 쓰게 한다.
2. AI가 후속 질문을 한다.
3. 막히면 문장 시작을 준다. 이후 조건을 바꿔 다시 묻는다.

| 관찰 결과 | 시작 방식 |
|---|---|
| 단어만 작성 또는 시작 불가 | 3안 수준의 문장 시작 힌트 |
| 한 문장 작성, 후속 질문에서 막힘 | 쉬운 1안 또는 짧은 2안 |
| 독립 답변과 후속 질문 대응 | 조건 추가, 힌트 축소 |

첫날 결과는 임시 배정이다. 3회 학습 뒤 다시 본다. 수능 성적이나 경과 일수만으로 난이도를 올리지 않는다.

`[가정]` 서로 다른 상황에서 같은 기능을 두 번 독립 수행하면 다음 학습에서 조건 하나를 추가한다. 실패하면 조건을 줄이거나 문장 시작을 제공한다. 문장 길이, 새 표현 수, 상대 발화 난도를 동시에 높이지 않는다.

타이핑 속도는 보조 관찰만 한다. 기기와 입력 습관의 영향을 받으므로 말하기 유창성으로 환산하지 않는다.

## 10. 성과 확인과 기록

기록은 사용자가 실제로 쓴 문장을 근거로 한다. AI의 총점 하나로 실력을 단정하지 않는다.

| 상태 | 기준 |
|---|---|
| 미완료 | 필요한 뜻의 전달 실패 또는 미응답 |
| 도움 후 수행 | 힌트나 예문 확인 후 과제 수행 |
| 독립 수행 | 새 상황에서 도움 없이 과제 수행 |
| 유지 확인 | 이후 학습일의 다른 상황에서 독립 수행 |

각 판정에는 사용자 답변과 과제의 필수 조건을 남긴다. AI가 고쳐 준 문장은 사용자 독립 성과에서 제외한다. 다른 표현으로 뜻을 전달해도 성공으로 인정한다.

`[가정]` 학습 지표는 새 상황의 독립 수행 과제 수 / 시도 과제 수로 둔다. 난도와 도움 여부가 비슷한 과제끼리 비교한다. 측정하지 않은 과제는 실패로 넣지 않는다.

| 세션 기록 | 활용 |
|---|---|
| 학습 시간, 회고 시간 | 습관 이행 확인 |
| 목표 기능과 상황 | 과정 진도, 다음 과제 선정 |
| 첫 답변과 수정 답변 | 개선 과정 확인 |
| 독립 답변과 힌트 사용 | 실제 수행 수준 확인 |
| 다음 복습 표현 | 다음 날 시작 과제 |
| 사용자의 회고 원문 | 아카이브, 독촉 근거 |
| 어려움과 다음 관심사 | 난도 조정, 소재 선택 |

독촉에 쓸 수 있는 사실 예: “어제는 시간 변경 요청을 혼자 쓰셨습니다.” 실제 독립 수행 기록이 있을 때만 쓴다. 앱 안 과제 성공을 현실에서 유창하게 말한 것으로 바꾸지 않는다. 학습 오류 자체를 독촉 재료로 삼지 않는 쪽을 제안한다.

`src/lib/ai.ts`는 사용자 발화 횟수에 따라 고정 문구를 돌려준다. 내용 이해나 학습 평가의 근거로 쓰지 않는다.

## 11. 3분 회고 연결

회고는 영어로 한다. 본 학습의 마지막 확인과 분리한다. 본 학습은 실제로 할 수 있는지를 확인한다. 회고는 사용자가 무엇을 느꼈고 다음에 무엇을 할지 묻는다.

| 시간 | 질문 예시 | 다음 학습의 활용 |
|---|---|---|
| 0~1분 | What was hard today? | 힌트와 교정 우선순위 |
| 1~2분 | Where could you use this? | 다음 상황 선택 |
| 2~3분 | What would you like to try next? | 후속 소재 선택 |

질문은 한 번에 하나만 보낸다. 답에 따라 짧은 후속 질문을 한다. 막히면 “It was hard to…” 같은 문장 시작을 준다. 영어로 길게 반성하게 만들지 않는다.

예: “I couldn't explain why.”라고 답하면 다음 날 변경 이유를 한 문장으로 쓰게 한다. “I want to use this at work.”라고 답하면 다음 상황을 회의 일정 변경으로 정한다.

2안에서는 하루 사건을 본 학습에서 이미 다뤘다. 회고에서는 표현의 어려움과 다음 사용처만 묻는다.

## 12. 봇과 운영에 주는 영향

### 12.1 기존 봇 후보

| 기존 후보 | 제안 | 근거 |
|---|---|---|
| 비즈니스 이메일 | 1안의 업무 메시지 과제로 축소 | 초반 장문 작성 부담 |
| 원어민 프리토킹 | 1안 상황 대화 또는 2안 질문 대화 | 시작할 주제와 끝낼 기준 필요 |
| IT 기사 3문장 요약 | 초기 기본 목록에서 보류 | 관심 분야 제한, 읽기 부담, 무입력 규칙 충돌 |
| 영단어 퀴즈 | 3안의 표현 사용 훈련으로 전환 | 뜻 인식 뒤 직접 사용 확인 필요 |

`[확인]` 대표 목표를 고른 뒤 기본 봇 개수를 정한다. 현재 4개를 반드시 유지할 이유는 없다. 커스텀 봇은 유지하되 서비스 공통 말투와 평가 규칙은 공유하는 쪽을 제안한다.

### 12.2 AI 호출 수 초안

`[가정]` AI 응답 한 번에 모델 호출 한 번이다. 시작 과제에 1회, 사용자 답변 처리에 매번 1회가 든다. 아래는 실제 이용 전 추정이다.

| 안 | 본 학습 시작 | 본 학습 답변 처리 | 회고 시작과 답변 처리 | 합계 |
|---|---|---|---|---|
| 1안 | 1회 | 8~12회 | 3~5회 | 12~18회 |
| 2안 | 1회 | 6~10회 | 3~5회 | 10~16회 |
| 3안 | 1회 | 10~16회 | 3~5회 | 14~22회 |

마지막 답변 처리에 기록 정리를 포함한다고 가정했다. 별도 평가 호출을 쓰면 그만큼 늘어난다. 온보딩, 재시도, 다음 문제 추가는 표에서 제외했다. 30분 사용자의 수요는 별도 실측해야 한다.

응답은 짧게 유지한다. 전체 과거 대화 대신 현재 세션과 필요한 학습 기록을 전달한다. 호출 수 외에도 입력 길이와 출력 길이가 원가를 좌우한다. 모델 선정 전에는 금액을 확정하지 않는다.

`[확인]` 무료 일일 상한은 5~30분 사용과 회고를 실측한 뒤 정한다. 상한 때문에 필수 회고를 못 끝내는 설계는 피한다. 세션 시작 시 필요한 사용량을 확보하는 방식이나 상한 도달 후 학습 대체 방식을 함께 정해야 한다.

### 12.3 프롬프트 설계의 다음 단계

이번 문서는 목표 선택용이다. 시스템 프롬프트 전체는 목표 선택 뒤 작성한다. 공통 조건은 학습 목표, 남은 시간, 현재 단계, 사용자 도움 수준, 최근 표현이다.

- 1안: 필수 전달 정보와 상대의 반응 조건.
- 2안: 사용자가 실제 말한 사건과 아직 묻지 않은 내용.
- 3안: 복습 대상과 힌트 사용 여부.

자유로운 역할 설명만으로 세션을 맡기지 않는다. 완료와 시간 판정은 앱이 맡는다. AI는 대화와 학습 피드백을 맡는다.

## 13. 선택 전에 확인할 것

1. `[확인]` 대표 학습 목표. 상황 해결, 자기 경험 설명, 표현 회상 중 선택. 추천은 상황 해결.
2. `[확인]` 시간 약속. 학습 15분 유지 또는 전체 이용 시간 15분에 맞춘 재설계. 현재 안은 전자.
3. `[확인]` 기본 봇의 전송 제한. 추천은 최소 글자 수 완화와 과제별 답변 안내.

선택한 안은 가짜 초보에게 실제 15분 동안 진행해 본다. 첫 문장을 쓰기까지 막히는 지점과 힌트 사용을 기록한다. 다음 학습일에는 다른 상황으로 다시 확인한다. 완료율과 함께 독립 수행 여부를 본다.

대표 목표가 정해지면 세션 상세 흐름, 기본 봇 목록, 시스템 프롬프트, 무료 호출 상한을 구체화한다.
